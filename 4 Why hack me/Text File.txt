TryHackMe – WhyHackMe машины нэвтрэлтийн туршилтын тайлан
1. Удиртгал
Энэхүү лабораторийн ажлын хүрээнд TryHackMe платформын WhyHackMe нэртэй виртуал машины аюулгүй байдлын түвшинг шалгаж, системд үүссэн эмзэг байдал болон буруу тохиргоонуудыг илрүүлэх зорилгоор нэвтрэлтийн туршилт хийж гүйцэтгэлээ. Туршилтын явцад Kali Linux үйлдлийн системийг ашиглан зорилтот машины сүлжээний үйлчилгээнүүдийг судалж, FTP болон HTTP үйлчилгээний мэдээлэл цуглуулах, веб програмын эмзэг байдлыг илрүүлэх, хэрэглэгчийн эрхээр системд нэвтрэх, сүлжээний траффикийг задлан шинжлэх, улмаар эрхийн түвшинг нэмэгдүүлж root хэрэглэгчийн эрх авах зэрэг үе шаттай ажиллагааг хэрэгжүүлсэн.

Энэхүү туршилт нь зөвхөн системд нэвтрэхээс гадна эмзэг байдал хэрхэн үүсдэг, халдагч тухайн эмзэг байдлыг ямар дарааллаар ашиглаж болох, байгууллагын системд ийм төрлийн сул талууд ямар эрсдэл учруулж болохыг ойлгоход чиглэсэн болно.
2. Туршилтын орчин
Туршилтыг Kali Linux болон TryHackMe платформоос өгсөн WhyHackMe виртуал машины хооронд VPN холболт ашиглан гүйцэтгэсэн. Kali Linux үйлдлийн системийг халдлагын туршилт хийх үндсэн орчин болгон ашигласан бол WhyHackMe машин нь эмзэг байдал илрүүлэх, шалгах зорилтот систем болсон.

Туршилтын явцад Kali Linux-ийн сүлжээний хаяг 192.168.134.122, зорилтот машины хаяг 10.113.171.149 байсан. Мөн системтэй холбогдох, мэдээлэл цуглуулах болон шинжилгээ хийхдээ FTP, SSH, HTTP, HTTPS, Netcat, Wireshark, curl, ffuf зэрэг хэрэгслүүдийг ашигласан.
3. FTP үйлчилгээний шинжилгээ ба мэдээлэл цуглуулалт
Нэвтрэлтийн туршилтын эхний үе шатанд зорилтот машины FTP үйлчилгээг шалгаж, хэрэглэгчийн нэр болон нууц үг шаардахгүйгээр нэвтрэх боломж байгаа эсэхийг туршсан. Үүний тулд Kali Linux терминал дээр FTP клиент ашиглан зорилтот машинтай холбогдсон.
ftp 10.113.171.149


Холболт хийх үед хэрэглэгчийн нэр асуухад anonymous гэсэн утгыг оруулсан. Ингэснээр FTP серверт Anonymous Access буюу нэр нууц үггүй зочны хандалтаар нэвтрэх боломжтой эсэхийг шалгасан. Нэвтэрсний дараа сервер дээр байрлах update.txt файлыг татаж авч агуулгыг нь уншсан.

Уг файлд өмнө нь ашиглаж байсан mike хэрэглэгчийн бүртгэл алдагдсан тул устгасан тухай, мөн шинэ хэрэглэгчийн мэдээлэл 127.0.0.1/dir/pass.txt замд байрлаж байгаа тухай мэдээлэл байсан. Гэхдээ уг замд зөвхөн локал хост буюу серверийн өөрийн орчноос хандах боломжтой гэж тэмдэглэсэн байв.

Энэ нь FTP сервер дээрх Anonymous Access тохиргоо нь дотоод мэдээллийг зөвшөөрөлгүй этгээдэд ил гаргах эрсдэлтэй байгааг харуулсан. Хэрэв байгууллагын бодит сервер дээр ийм тохиргоо байвал нууц мэдээлэл, тохиргооны файл болон хэрэглэгчийн мэдээлэл алдагдах боломжтой.
4. Веб серверийн бүтэц болон замуудыг илрүүлэх
FTP-ээс авсан мэдээлэлд үндэслэн зорилтот машины веб серверийг шинжилж, ямар веб хуудас болон директорууд нийтэд нээлттэй байгааг тодорхойлох дараагийн алхмыг хийсэн. Эхлээд whatweb хэрэгслийг ашиглан веб серверийн технологи болон хувилбарын мэдээллийг шалгасан.
whatweb http://10.113.171.149


Шинжилгээний үр дүнд Apache HTTP Server 2.4.41 болон Ubuntu орчинд ажиллаж буй PHP веб програм байгааг илрүүлсэн. Мөн веб програм хэрэглэгчийн session удирдахад PHPSESSID cookie ашиглаж байгааг ажигласан.

Үүний дараа ffuf хэрэгслээр веб серверийн нийтэд харагдахгүй директор болон файлын нэрсийг автоматаар шалгасан. Энэ ажиллагааг Directory Enumeration гэж нэрлэдэг бөгөөд веб сервер дээр байрлаж байгаа боловч үндсэн хуудсанд холбоосгүй байж болох замуудыг илрүүлэхэд ашигладаг.
ffuf -u http://10.113.171.149/FUZZ \
-w /usr/share/wordlists/dirb/common.txt


Шалгалтын үр дүнд assets, dir, index.php зэрэг замууд илэрсэн. Зарим замд HTTP 403 буюу Forbidden хариу ирсэн нь тухайн нөөц байгаа боловч шууд хандах эрх хязгаарлагдсан болохыг илэрхийлж байв.

Мөн PHP өргөтгөлтэй файлуудыг тусад нь шалгаснаар register.php, login.php, blog.php, config.php, index.php, logout.php зэрэг веб програмын хэсгүүдийг илрүүлсэн. Эдгээр хуудсуудыг судалснаар хэрэглэгчийн бүртгэл үүсгэх, системд нэвтрэх, нийтлэл болон сэтгэгдэлтэй ажиллах боломжтой веб програм байгааг тогтоосон.
5. Stored XSS эмзэг байдлыг илрүүлэх
Веб програмын бүртгэл болон блогийн хэсгийг шалгах явцад хэрэглэгчийн оруулсан мэдээллийг сервер талд хангалттай шүүж, аюулгүй боловсруулж байгаа эсэхийг туршсан. Үүний тулд лабораторийн орчинд тестийн хэрэглэгчийн бүртгэл үүсгэж, хэрэглэгчийн нэрийн талбарт JavaScript код оруулан шалгасан.

Ашигласан тестийн утга:
<script>alert('1')</script>


Бүртгэл үүсгэсний дараа блогийн хэсэгт сэтгэгдэл бичиж, тухайн хэрэглэгчийн нэр веб хуудсанд хэрхэн харагдаж байгааг шалгасан. Үүний үр дүнд JavaScript код веб хуудас дотор ажиллаж, alert('1') гэсэн цонх гарч ирсэн.

Энэ нь Stored Cross-Site Scripting буюу Stored XSS эмзэг байдал байгааг баталсан. Stored XSS гэдэг нь хэрэглэгчийн оруулсан хортой JavaScript код серверийн өгөгдлийн санд хадгалагдаж, дараа нь тухайн мэдээллийг харж буй бусад хэрэглэгчийн браузер дээр ажиллах боломжтой эмзэг байдал юм.

Энэ тохиолдолд хэрэглэгчийн нэрийн талбарт оруулсан JavaScript кодыг веб програм аюулгүй байдлаар боловсруулалгүйгээр хуудсанд буцаан харуулж байсан. Өөрөөр хэлбэл, хэрэглэгчийн оруулсан өгөгдлийг HTML контекстэд зөв escape хийх, шүүх хамгаалалт хангалтгүй байсан гэж дүгнэсэн.

Stored XSS эмзэг байдлыг ашигласнаар хэрэглэгчийн браузер дээр зөвшөөрөлгүй JavaScript ажиллуулах, session мэдээлэлд халдах, хэрэглэгчийн өмнөөс үйлдэл хийх зэрэг эрсдэл үүсэж болно. Туршилтын дараагийн шатанд энэхүү эмзэг байдлыг ашиглан серверийн локал орчинд байрлах мэдээлэлд хандах ажиллагааг лабораторийн хүрээнд шалгасан.
6. Локал мэдээлэлд хандаж SSH хэрэглэгчийн мэдээллийг илрүүлэх
FTP-ээс авсан update.txt файлд дурдсан 127.0.0.1/dir/pass.txt зам нь серверийн локал орчноос хандах зориулалттай байсан. Иймээс веб програмын Stored XSS эмзэг байдлыг ашиглан тухайн локал замаас текст мэдээлэл унших боломжийг туршсан.

Лабораторийн орчинд JavaScript ашиглан локал веб зам руу HTTP хүсэлт илгээж, буцаж ирсэн хариуг туршилтын Kali Linux машин дээр ажиллаж байсан HTTP сервер рүү дамжуулсан. Үүний үр дүнд локал орчинд байрлах мэдээллийг гаднаас шууд унших боломжгүй байсан ч веб хэрэглэгчийн браузерын эрх болон Stored XSS эмзэг байдлыг дамжуулан авч болохыг харуулсан.

Ингэснээр jack хэрэглэгчийн SSH-д ашиглах мэдээллийг олж авч, зорилтот машин руу SSH протоколоор холбогдох боломж бүрдсэн.
7. SSH үйлчилгээгээр системд нэвтрэх
Өмнөх шатанд олж авсан хэрэглэгчийн мэдээллийг ашиглан зорилтот машины SSH үйлчилгээнд холбогдсон. SSH нь алсын төхөөрөмжид шифрлэгдсэн сувгаар команд ажиллуулах боломж олгодог протокол юм.
ssh jack@10.113.171.149


Холболтын үед jack хэрэглэгчийн нууц үгийг оруулж системд нэвтэрсэн. Амжилттай нэвтэрсний дараа хэрэглэгчийн үндсэн директор болон системийн боломжтой файлуудыг шалгасан.

Эхний ээлжид хэрэглэгчийн flag байрлаж буй файлыг уншсан.
cat user.txt


Үр дүнд дараах User flag гарсан.
User flag
1ca4eb201787acbfcf9e70fca87b866a

Энэ нь jack хэрэглэгчийн эрхээр зорилтот системд амжилттай нэвтэрч, хэрэглэгчийн түвшний даалгаврыг гүйцэтгэсэн болохыг баталсан.
8. Firewall тохиргоог шинжлэх
SSH холболт амжилттай болсны дараа системийн сүлжээний хамгаалалтын тохиргоог шалгах зорилгоор iptables командыг ашигласан.
sudo iptables -L -n -v


iptables нь Linux үйлдлийн системийн сүлжээний пакетуудад дүрэм хэрэгжүүлэх, тодорхой порт болон IP хаягийн урсгалыг зөвшөөрөх эсвэл хориглох зориулалттай firewall удирдах хэрэгсэл юм.

Шалгалтын үр дүнд TCP 41312 портын урсгалд DROP дүрэм үйлчилж байгааг илрүүлсэн. Мөн loopback интерфэйсийн урсгалыг зөвшөөрсөн болон бусад урсгалд хамаарах ACCEPT, DROP дүрмүүд байв. Иймээс Apache серверийн тусгай порт руу гаднаас шууд холбогдох боломжийг firewall хязгаарлаж байсан гэж үзсэн.

Үүний дараа системийн /opt/urgent.txt файлыг уншиж, администраторын үлдээсэн тэмдэглэлтэй танилцсан.
cat /opt/urgent.txt


Уг файлд /usr/lib/cgi-bin/ директор дотор тодорхой файлууд байрлаж байгаа, тэдгээрийг устгах боломжгүй байгаа, мөн /opt/capture.pcap файлыг шалгах шаардлагатай тухай дурдсан байв. Түүнчлэн backdoor буюу далд хандалтын боломжийг firewall ашиглан түр хаасан тухай мэдээлэл байсан.

Энэ мэдээлэл нь дараагийн шинжилгээнд PCAP файлыг судлах, Apache CGI тохиргоог шалгах шаардлагатайг харуулсан.
9. Apache тохиргоо болон CGI файлыг судлах
Дараагийн шатанд Apache веб серверийн тохиргоог шалгаж, 41312 портын хэрэглээ болон CGI скриптийн байршлыг тодорхойлсон.
cat /etc/apache2/sites-available/000-default.conf


Тохиргооны файлд Apache сервер 41312 портыг сонсож байгаа, TLS шифрлэлт ашиглаж байгаа, мөн CGI скриптүүдийг /usr/lib/cgi-bin/ директороос ажиллуулах тохиргоотой байгааг илрүүлсэн.

Мөн TLS сертификат болон хувийн түлхүүрийн файлууд дараах замд байрлаж байв.
/etc/apache2/certs/apache-certificate.crt
/etc/apache2/certs/apache.key


Apache-ийн ScriptAlias тохиргоо нь /cgi-bin/ URL замыг серверийн /usr/lib/cgi-bin/ директор руу холбож байсан. Харин AddHandler тохиргоогоор .cgi, .py, .pl өргөтгөлтэй файлуудыг CGI скрипт хэлбэрээр ажиллуулахаар тохируулсан байв.

Энэ тохиргоо нь сервер дээрх Python скриптийг веб хүсэлтээр ажиллуулах боломж олгодог. Хэрэв тухайн скриптэд баталгаажуулалт, оролтын шалгалт болон командын гүйцэтгэлийн хамгаалалт хангалтгүй байвал халдагч сервер дээр зөвшөөрөлгүй команд ажиллуулах эрсдэлтэй.
10. PCAP файлыг Wireshark ашиглан шинжлэх
urgent.txt файлд дурдсан /opt/capture.pcap файлыг Kali Linux орчинд хуулж авч, Wireshark ашиглан сүлжээний траффикийг шинжилсэн. PCAP файл нь сүлжээгээр дамжсан пакет болон холболтын мэдээллийг хадгалдаг тул өмнө нь ямар хүсэлт илгээгдсэн, ямар хариу буцсан, сервер ямар үйлчилгээ ажиллуулсан зэргийг судлахад ашиглагддаг.

Тухайн PCAP файлд HTTPS буюу TLS шифрлэлттэй HTTP хүсэлтүүд байсан. Эдгээр хүсэлтийг шууд унших боломжгүй байсан тул Apache серверийн хувийн түлхүүрийг ашиглан Wireshark-ийн TLS RSA keys тохиргоонд түлхүүрийг бүртгэж, боломжтой траффикийг задлан шинжилсэн.

Задалсан урсгал дотроос дараах HTTP хүсэлт илэрсэн.
GET /cgi-bin/5UP3r53Cr37.py?key=48pfPHUrj4pmHzrC&iv=VZukhsCo8TlTXORN&cmd=id HTTP/1.1
Host: 10.0.2.15:41312


Энэ хүсэлт нь Apache серверийн CGI директор дотор байрлах 5UP3r53Cr37.py Python скриптийг ажиллуулж, id командыг гүйцэтгэхээр дамжуулж байгааг харуулсан.

Серверийн буцаасан хариунд:
uid=33(www-data) gid=1003(h4ck3d) groups=1003(h4ck3d)


гэж гарсан. Энэ нь тухайн CGI скриптээр дамжуулан Linux системийн команд ажиллуулах боломж байгааг нотолсон. Ийм төрлийн скрипт нь гаднаас ирсэн хүсэлтийн параметрийг хангалттай шалгахгүйгээр системийн командтай холбосон тохиолдолд Remote Code Execution буюу алсаас команд ажиллуулах эмзэг байдал үүсгэж болно.

Энд Host: 10.0.2.15 гэж харагдсан нь PCAP файлд хадгалагдсан хуучин сүлжээний орчны хаяг бөгөөд тухайн туршилтын одоогийн зорилтот машины VPN хаяг 10.113.171.149 байсныг ялгаж ойлгох шаардлагатай.
11. Firewall дүрмийг өөрчилж CGI backdoor-т хандах
PCAP шинжилгээгээр CGI скриптийн URL болон шаардлагатай параметрүүдийг тодорхойлсны дараа jack хэрэглэгчийн эрхээр iptables дүрмийг шалгаж, лабораторийн орчинд firewall дүрмүүдийг цэвэрлэсэн.
sudo iptables -F


Энэ команд нь iptables-ийн одоо байгаа filter хүснэгтийн chain-үүдийн дүрмүүдийг устгадаг. Үүний дараа дүрмүүдийг дахин шалгасан.
sudo iptables -L -n


Үр дүнд нь chain-үүдэд байсан дүрмүүд арилсан байв. Ийнхүү лабораторийн машин дээрх 41312 портын хандалтыг хязгаарлаж байсан firewall дүрмийг арилгасны дараа Kali Linux-оос CGI скрипт рүү HTTPS хүсэлт илгээсэн.
curl -k 'https://10.113.171.149:41312/cgi-bin/5UP3r53Cr37.py?key=48pfPHUrj4pmHzrC&iv=VZukhsCo8TlTXORN&cmd=id'


Энд curl нь HTTP болон HTTPS хүсэлт илгээх хэрэгсэл бөгөөд -k параметр нь лабораторийн орчинд сертификатын баталгаажуулалтын алдааг үл тоомсорлон холболт хийхэд ашиглагдсан. Хүсэлтийн үр дүнд серверээс www-data хэрэглэгчийн мэдээлэл буцаж ирсэн нь CGI скрипт ажиллаж байгааг баталсан.

Энэ шат нь CGI скриптийн буруу тохиргоо болон firewall-ийн хамгаалалтыг өөрчилж болох эрхийн нийлбэр нь системийн аюулгүй байдалд хэрхэн нөлөөлж болохыг харуулсан.
12. Reverse Shell холболт үүсгэх
CGI скриптээр дамжуулан системийн команд ажиллуулах боломжтой нь батлагдсаны дараа Kali Linux болон зорилтот машины хооронд Reverse Shell холболт үүсгэсэн. Reverse Shell гэдэг нь зорилтот машин өөрөө халдагчийн удирдаж буй компьютер руу сүлжээний холболт үүсгэж, алсын терминалаар команд ажиллуулах боломж олгодог арга юм.

Эхлээд Kali Linux дээр Netcat ашиглан 9001 портыг сонсох горимд ажиллуулсан.
nc -lvnp 9001


Дараа нь CGI скриптэд команд дамжуулж, зорилтот машинаас Kali Linux-ийн 192.168.134.122 хаягийн 9001 порт руу холболт үүсгэсэн. Ингэснээр Kali Linux дээр ажиллаж байсан Netcat listener холболтыг хүлээн авч, зорилтот машины shell нээгдсэн.

Терминалд дараах холболтын мэдээлэл гарсан.
connect to [192.168.134.122] from (UNKNOWN) [10.113.171.149] 33810


Энэ нь зорилтот 10.113.171.149 машинаас Kali Linux-ийн 192.168.134.122 хаяг руу амжилттай холболт үүссэнийг илэрхийлнэ.

Reverse Shell дотор дараах командыг ажиллуулж хэрэглэгчийн эрхийг шалгасан.
whoami


Үр дүнд:
www-data


гэж гарсан. Мөн:
id


командын үр дүнд:
uid=33(www-data) gid=1003(h4ck3d) groups=1003(h4ck3d)


гэж гарсан. Иймээс CGI скриптээр дамжуулан үүсгэсэн Reverse Shell нь Apache веб серверийн www-data хэрэглэгчийн эрхээр ажиллаж байгааг баталсан.
13. Privilege Escalation буюу эрхийн түвшин нэмэгдүүлэх
Reverse Shell-ээр www-data хэрэглэгчийн эрхтэй холбогдсоны дараа системийн хэрэглэгчид ямар эрхтэй команд ажиллуулах боломжтойг шалгах зорилгоор дараах командыг ашигласан.
sudo -l


Энэ команд нь тухайн хэрэглэгчид sudo ашиглан ямар командуудыг ямар нөхцөлтэй ажиллуулах эрх олгогдсоныг харуулдаг.

Шалгалтын үр дүнд:
User www-data may run the following commands on ubuntu:
    (ALL : ALL) NOPASSWD: ALL


гэсэн мэдээлэл гарсан. Энэ нь www-data хэрэглэгч ямар ч командыг дурын хэрэглэгчийн эрхээр, нууц үг оруулахгүйгээр ажиллуулах боломжтой байгааг илэрхийлнэ.

Энд NOPASSWD: ALL гэсэн тохиргоо нь хамгийн чухал эмзэг байдал болсон. Учир нь веб серверийн процесс ихэвчлэн хязгаарлагдмал эрхтэй хэрэглэгчээр ажиллах ёстой боловч уг системд www-data хэрэглэгчид бүх командыг root эрхээр ажиллуулах боломж олгосон байв.

Үүний дараа дараах командыг ажиллуулсан.
sudo su


Энэ команд нь root хэрэглэгчийн shell рүү шилжих зориулалттай. Амжилттай шилжсэний дараа root хэрэглэгчийн эрхээр /root/root.txt файлыг уншсан.
cat /root/root.txt


Үүний үр дүнд дараах Root flag гарсан.
Root flag
4dbe2259ae53846441cc2479b5475c72

Ингэснээр лабораторийн зорилтот системд энгийн хэрэглэгчийн эрхээс эхлэн веб серверийн хэрэглэгчийн эрхээр дамжин root түвшинд хүрэх ажиллагааг амжилттай гүйцэтгэсэн.
14. Илрүүлсэн эмзэг байдал болон эрсдэлийн үнэлгээ
Туршилтын явцад илэрсэн гол эмзэг байдал, тэдгээрийн нөлөөллийг дараах байдлаар нэгтгэв.
Илэрсэн эмзэг байдал	Болзошгүй эрсдэл
FTP Anonymous Access	Дотоод болон нууц мэдээлэл зөвшөөрөлгүй этгээдэд ил гарах
Stored XSS	Хэрэглэгчийн браузер дээр зөвшөөрөлгүй JavaScript ажиллах
CGI скриптийн командын гүйцэтгэлийн сул хамгаалалт	Сервер дээр алсаас команд ажиллуулах боломж үүсэх
TLS хувийн түлхүүрийн хамгаалалт хангалтгүй байх	Шифрлэгдсэн траффикийг задлах эрсдэл үүсэх
www-data хэрэглэгчид NOPASSWD: ALL олгосон	Веб серверийн эрх алдагдвал root эрхэд шууд хүрэх боломж үүсэх
Firewall-ийн дүрмийг өөрчлөх эрх	Сүлжээний хамгаалалтын хязгаарлалтыг арилгах боломж үүсэх

Эдгээр эмзэг байдлыг тус тусад нь авч үзэхээс гадна хоорондын уялдаа холбоог анхаарах шаардлагатай. Тухайлбал, Stored XSS нь локал мэдээлэлд хандах боломжийг бүрдүүлж, хэрэглэгчийн мэдээлэл алдагдсанаар SSH нэвтрэлт хийх нөхцөл үүссэн. Дараа нь CGI скриптийн сул хамгаалалт ашиглагдаж www-data эрхтэй shell авсан бөгөөд sudo тохиргооны алдаа нь root эрхэд хүрэх боломжийг олгосон.
15. Аюулгүй байдлыг сайжруулах санал
Ийм төрлийн халдлагаас урьдчилан сэргийлэхийн тулд FTP үйлчилгээнд Anonymous Access тохиргоог шаардлагагүй тохиолдолд бүрэн идэвхгүй болгох, шаардлагатай тохиолдолд зөвхөн унших эрхтэй, хязгаарлагдмал директор ашиглах хэрэгтэй. Мөн нууц мэдээлэл болон хэрэглэгчийн нэвтрэх мэдээллийг веб серверийн нийтэд хандах боломжтой директоруудад байрлуулахгүй байх шаардлагатай.

Веб програмын хувьд хэрэглэгчээс ирсэн бүх өгөгдлийг сервер талд шалгаж, HTML контекстэд буцаан харуулахдаа зөв escape хийх хэрэгтэй. JavaScript кодыг хэрэглэгчийн оруулсан өгөгдөлтэй шууд холбож ажиллуулахгүй байх, Content Security Policy буюу CSP бодлогыг хэрэгжүүлэх нь XSS халдлагын эрсдэлийг бууруулна.

Apache CGI скриптүүдэд шаардлагагүй системийн команд ажиллуулах боломж олгохгүй байх, хэрэглэгчийн хүсэлтээс ирсэн параметрүүдийг найдвартай шалгах, командын оролтыг shell-д шууд дамжуулахгүй байх нь чухал. Мөн CGI скриптүүдийг тусгай хязгаарлагдмал хэрэглэгчийн эрхээр ажиллуулах шаардлагатай.

TLS хувийн түлхүүрийг зөвхөн шаардлагатай администратор унших эрхтэй байхаар хамгаалж, нууц түлхүүрийн хуулбарыг PCAP болон бусад шинжилгээний файлуудтай хамт хяналтгүй хадгалахгүй байх хэрэгтэй. Харин firewall-ийн дүрмийг зөвхөн эрх бүхий администратор өөрчлөх боломжтой болгож, бүх дүрмийн өөрчлөлтийг бүртгэж хянах шаардлагатай.

Хамгийн чухал нь www-data зэрэг веб серверийн хэрэглэгчид NOPASSWD: ALL эрх олгохгүй байх хэрэгтэй. Системийн хэрэглэгч бүрт зөвхөн ажлаа гүйцэтгэхэд шаардлагатай хамгийн бага эрхийг олгох зарчмыг хэрэгжүүлэх нь privilege escalation халдлагаас хамгаалах үндсэн арга юм.
16. Дүгнэлт
WhyHackMe виртуал машинд хийсэн нэвтрэлтийн туршилтаар системийн аюулгүй байдалд сөргөөр нөлөөлж болох хэд хэдэн эмзэг байдал болон буруу тохиргоог илрүүлж, тэдгээрийн уялдаа холбоог практик орчинд судаллаа. Туршилтын эхний шатанд FTP Anonymous Access тохиргоог ашиглан серверийн мэдээлэл цуглуулж, веб серверийн директор болон файлуудыг илрүүлсэн. Үүний дараа хэрэглэгчийн нэрийн талбарт Stored XSS эмзэг байдлыг баталгаажуулж, веб програмын хамгаалалт хангалтгүй байгааг тогтоосон.

Цаашлаад олж авсан мэдээллийг ашиглан SSH үйлчилгээнд jack хэрэглэгчээр нэвтэрч, системийн firewall болон Apache серверийн тохиргоог судалсан. Wireshark хэрэгслээр PCAP файлыг задлан шинжлэх явцад TLS шифрлэлттэй HTTP хүсэлтийн агуулгыг сэргээж, Apache CGI скриптээр дамжуулан системийн команд ажиллуулах боломж байгааг илрүүлсэн. Үүний дараа Kali Linux дээр Netcat listener ажиллуулж, зорилтот машинаас Reverse Shell холболт үүсгэн www-data хэрэглэгчийн эрхтэйгээр системд нэвтэрсэн.

Эцсийн шатанд sudo -l командаар www-data хэрэглэгчид NOPASSWD: ALL эрх олгосон ноцтой буруу тохиргоог илрүүлсэн. Энэ тохиргоог ашиглан root хэрэглэгчийн эрхэд шилжиж, /root/root.txt файлыг уншсанаар Root flag-ийг амжилттай авсан.

Энэхүү лабораторийн ажил нь нэг системд олон төрлийн эмзэг байдал зэрэг оршиж болох бөгөөд тэдгээрийг дараалалтай ашиглахад энгийн хэрэглэгчийн түвшнээс системийн бүрэн удирдлагын эрх хүртэл хүрэх эрсдэлтэйг харууллаа. Мөн нэвтрэлтийн туршилтын явцад мэдээлэл цуглуулах, эмзэг байдал баталгаажуулах, сүлжээний траффик шинжлэх, эрхийн түвшин нэмэгдүүлэх зэрэг ажиллагааг зөв дарааллаар гүйцэтгэх нь чухал болохыг практик байдлаар ойлгож авсан.

Тайланд оруулах screenshot-уудын санал болгож буй дараалал:
1. FTP серверт Anonymous Access ашиглан холбогдсон терминал.
2. update.txt файлын агуулга.
3. whatweb болон ffuf командын үр дүн.
4. Stored XSS ажиллаж буй браузерын цонх.
5. SSH-ээр jack хэрэглэгчээр нэвтэрсэн терминал.
6. user.txt файлын User flag.
7. iptables -L -n -v командын үр дүн.
8. Apache 000-default.conf тохиргоо.
9. Wireshark дээр TLS траффик задлагдсан HTTP хүсэлт.
10. CGI backdoor-ийн curl хүсэлтийн хариу.
11. Netcat дээр Reverse Shell холболт үүссэн үр дүн.
12. sudo -l командын NOPASSWD: ALL үр дүн.
13. Root эрх болон Root flag харуулсан терминал.
Тайлбар: Тайланд зөвхөн өөрийн туршилтаар авсан бодит screenshot-уудыг ашиглаарай. sudo su командын дараа whoami ажиллуулж root гэж гарсан үр дүнг нэмбэл root эрхэд шилжсэнээ илүү тодорхой нотолно.
