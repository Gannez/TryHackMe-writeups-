Zeno Machine - Бүрэн Эвдлэлтийн Тайлан
Нэгдүгээр үе шат: Сүлжээний судалгаа (Reconnaissance)

Ажлыг эхлүүлэхийн тулд эхлээд зорилтот машины IP хаягийг $IP хувьсагч болгон тохируулсан. Үүний дараа nmap хэрэгслийг ашиглан порт сканнердаж, зорилтот машин дээр хоёр порт нээлттэй байгааг тогтоосон: 22-р порт дээр OpenSSH 7.4 үйлчилгээ, харин 12340-р порт дээр HTTP вэб сервер ажиллаж байв. Энэхүү анхны судалгаа нь дараагийн бүх алхмуудын суурь болсон бөгөөд ямар сувгаар дайрах боломжтойг тодорхойлоход тусалсан.

Хоёрдугаар үе шат: Вэб аппликейшн илрүүлэлт

12340-р порт дээрх вэб серверт хандахад stock 404 алдааны хуудас харагдсан тул аппликейшны дотоод бүтцийг илрүүлэх шаардлагатай болсон. Browser ашиглан шууд хандаж, /rms/ замыг олсноор “Pathfinder Hotel Restaurant Management System” нэртэй вэб аппликейшн ажиллаж байгааг тогтоосон. Энэ бол PHP хэл дээр бичигдсэн, ресторан менежментийн зориулалттай нээлттэй эх кодын систем байв.

Гуравдугаар үе шат: Эмзэг байдлыг хайх

Аппликейшны нэрийг ашиглан searchsploit хэрэгслээр хайлт хийхэд хоёр мэдэгдэж буй эмзэг байдал олдсон: нэг нь SQL Injection, нөгөө нь Remote Code Execution (RCE) байв. RCE эмзэг байдлыг ашиглах exploit script-ийг хуулбарлан авч агуулгыг нь шинжилсэн бөгөөд энэ нь нэвтрэлт (authentication) шаардахгүйгээр файл байршуулах боломж олгодог нь илэрсэн. Эх script нь зарим талаараа тохиромжгүй байсан тул (hardcoded proxy, шаардлагагүй header-үүд гэх мэт) үүнийг цэвэрлэж, зорилтот машинд тохируулан дахин бичсэн.

Дөрөвдүгээр үе шат: Анхны нэвтрэлт (Initial Foothold)

Шинэчлэгдсэн exploit script-ийг ашиглан, зорилтот сервер рүү PHP reverse shell файл амжилттай байршуулсан. Байршуулсны дараа, attacker машин дээр netcat listener ажиллуулж, upload хийгдсэн PHP файлыг trigger хийснээр сервер нь холбогдож, тушаалын мөр (shell) нээгдсэн. Энэ үед хийгдсэн id команд нь shell-ийг apache хэрэглэгчийн эрхээр авсныг баталсан — энэ бол вэб серверийг ажиллуулдаг, хязгаарлагдмал эрхтэй системийн хэрэглэгч юм.

Тавдугаар үе шат: Дотоод судалгаа ба мэдээлэл цуглуулалт

Apache хэрэглэгчийн эрхээр системд орсны дараа дараагийн зорилго нь эрх өсгөх (privilege escalation) байв. Эхлээд /etc/passwd файлыг уншиж, системд ямар жирийн (non-system) хэрэглэгчид бүртгэлтэй болохыг шалгасан бөгөөд edward нэртэй нэг хэрэглэгч олдсон. Дараа нь аппликейшны өгөгдлийн сангийн тохиргооны файлуудыг (config.php) хайж олоод уншихад database-ийн нэвтрэлт мэдээлэл тодоор (plaintext) бичигдсэн байсан боловч энэ нь edward хэрэглэгчид тохироогүй.

Үүний дараа Linpeas гэдэг автоматжуулсан privilege escalation судалгааны скриптийг attacker машинаас HTTP server-ээр дамжуулан зорилтот машин руу татаж, ажиллуулсан. Linpeas-ийн гаргасан тайланд хоёр чухал олдворыг илрүүлсэн:

Нэгдүгээрт, /etc/fstab файлд zeno нэртэй хэрэглэгчийн нэвтрэлт мэдээлэл (хэрэглэгчийн нэр, нууц үг) тодоор бичигдсэн байв. Энэ нь network share mount хийх зориулалттай тохиргооны мөрөнд дурдагдсан боловч аюулгүй байдлын алдаа болж, системийн нууц мэдээлэл задарсан байдалд хүргэсэн.

Хоёрдугаарт, /etc/systemd/system/zeno-monitoring.service нэртэй systemd unit файл нь бүх хэрэглэгч бичих эрхтэй (world-writable) байсан нь илэрсэн. Энэ нь аюулгүй байдлын ноцтой алдаа бөгөөд учир нь уг файл нь root эрхээр ажилладаг systemd үйлчилгээг тодорхойлдог байв.

Зургаадугаар үе шат: edward хэрэглэгч рүү шилжих

Linpeas-ээс олдсон zeno хэрэглэгчийн нууц үгийг su edward командаар туршиж үзэхэд, нууц үг нь edward хэрэглэгчид бас тохирсон болох нь тогтоогдсон. Ингэснээр apache хэрэглэгчийн хязгаарлагдмал эрхээс гарч, edward хэрэглэгчийн эрхтэй болсон. Энэ үед /home/edward/user.txt файлаас user flag-ийг уншиж авсан.

Долдугаар үе шат: Root эрх авах бэлтгэл

Edward хэрэглэгчээр орсны дараа sudo -l командаар сангийн sudo эрхийг шалгахад, edward хэрэглэгч нь нууц үггүйгээр (NOPASSWD) /usr/sbin/reboot командыг ажиллуулах эрхтэй болох нь илэрсэн. Энэ нь өмнө нь илэрсэн writable systemd unit file-тэй хослуулбал, root эрх авах бүрэн боломжийг бий болгосон.

Логик нь энгийн: writable unit file-ийн агуулгыг solih боломжтой тул, тэнд root эрхээр ямар ч команд ажиллахаар бичиж болно. Харин энэ командыг ажиллуулахын тулд системийг дахин эхлүүлэх (reboot) шаардлагатай, учир нь systemd unit file нь зөвхөн boot процессын үед эсвэл service идэвхжсэн үед уншигддаг. Яг энд sudo /usr/sbin/reboot эрх хэрэг болсон юм.

Наймдугаар үе шат: Unit file-ийг өөрчлөх

Writable zeno-monitoring.service файлын агуулгыг бүхэлд нь шинэ командаар дарж бичсэн. Шинэ ExecStart мөрөнд дараах логикийг оруулсан: /bin/bash-ийн хуулбарыг /home/edward/bd нэртэй файл болгон хуулж, дараа нь энэ файлд SUID bit (chmod u+s) тавих. SUID bit гэдэг нь тухайн файлыг ямар ч хэрэглэгч ажиллуулахад, файлыг эзэмшигчийн (энэ тохиолдолд root) эрхээр ажиллуулна гэсэн онцгой зөвшөөрөл юм.

Есдүгээр үе шат: Reboot ба trigger

sudo /usr/sbin/reboot командыг ажиллуулснаар систем дахин эхэлсэн. Reboot процессын үед systemd нь бүх .service файлуудыг уншиж, тэдгээрийг идэвхжүүлдэг тул манай өөрчилсөн zeno-monitoring.service-ийн ExecStart команд root эрхээр автоматаар ажиллаж, /home/edward/bd нэртэй SUID bash binary-г бий болгосон.

Аравдугаар үе шат: Root shell авах

Систем дахин ассаны дараа SSH протоколоор edward хэрэглэгчийн эрхээр дахин нэвтэрсэн. Дараа нь /home/edward/bd файлын эрхийг шалгахад -rwsr-xr-x гэсэн permission харагдсан бөгөөд энд байгаа s тэмдэгт нь SUID bit амжилттай идэвхжсэнийг баталсан.

Эцэст нь /home/edward/bd -p командыг ажиллуулснаар (-p flag нь SUID эрхийг хадгалах зориулалттай) root эрхтэй bash shell нээгдсэн. whoami командаар шалгахад root гэж гарч ирснээр эрх өсгөлт бүрэн амжилттай болсныг баталгаажуулсан. Эцэст нь /root/root.txt файлаас root flag-ийг уншиж, machine-ийг бүрэн эзэмшсэнийг нотолсон.

Дүгнэлт

Энэхүү машин нь нэг гинжин холбоостой олон эмзэг байдлыг амжилттай ашигласан жишээ юм: unauthenticated file upload нь анхны нэвтрэлт олгож, plaintext credentials-ийн задрал нь хэрэглэгчийн шилжилтийг хялбарчилж, харин writable systemd unit file болон misconfigured sudo privilege хоёрын хослол нь эцсийн эцэст root эрх авахад хүргэсэн. Энэ бол жирийн web app-ийн алдаанаас эхлээд системийн тохиргооны алдаа хүртэл хэрхэн холбогдож, бүрэн эвдлэлтэд хүргэдгийн сайн жишээ юм.
